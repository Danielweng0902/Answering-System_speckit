## 121 筆逾時與封包大小

原始 WebSocket 的 8,000 路觀測中，送出者 5、同組 5、老師 57、投影 54，合計 121。量測器超過 5 秒即記逾時，即使稍後收到也維持原值；老師須在看板找到答案，舊投影須與老師 revision 配對（e2e/load/lib/socketLoad.mjs 第 190、273、299、395 行）。歷史版插樁重跑計得 1,263 路逾時，其中能直接觀察到晚到配對的至少有老師 112、投影 113、送出者 148、同組 148。原趟沒有逐包時間戳，無法逐筆回溯那 121 筆。老師封包到後段大約 316 KB，增加傳輸與客戶端掃描成本；約 8 KB 的歷史投影亦逾時。

另一次歷史版對照在暖身到第二輪結束後多留 3 秒，以每條 socket 在 open 階段的 state 筆數與有序 revision 滾動校驗值比對發送端與接收端。104 個歷來連線 ID（換組會重連）全部相符，**8,550 包**中老師 2,053、投影 2,053、學生 4,444，同一趟壓測器仍記 **1015** 路逾時。結合時間戳，此觀測將主要問題定位在排隊與 deadline；解析及配對的各自占比仍待量測；沒有觀察到封包因大小超限被丟棄。封包愈大仍會放大排隊。壓測客戶端也有同步工作，每次收到老師 state 會掃 1,000 格，單趟 2,000 次作答即約 200 萬格（e2e/load/lib/socketLoad.mjs 第 273–293 行）。

目前版本的同規模實測則有 **2,000／2,000** 個投影通道逾時，另有老師 472、送出者與同組各 3。工具的四路規則仍沿用舊版；恢復逐筆送給投影會洩漏作答時機與全場事件次數。現行版應驗證三路必要送達，另驗證投影零作答廣播及公開狀態轉換正常。原報告的 polling 在腳本裡固定 upgrade: false（e2e/load/lib/socketLoad.mjs 第 597–602 行），42.90% 是純 polling 的 ACK 逾時率。

## 修正順序與預估

以下估值都是每 50 筆作答可減少的**同步服務時間**。排隊縮短多少須重跑壓測，不能直接從 ACK p95 減去表內數值。

|---|---|---|---|
| 1 | answerProjections.ts:227 的 buildBoard 與 answerRepo.ts:246 的 listAllSubmissions。維護活動範圍內的已提交作答索引，首次或失效後批讀，平時在交易成功後更新受影響的題與組，從同一視圖產生完整老師看板。 | 歷史後段 50 次光讀全場花 350.9 ms。若增量更新花原讀取成本的 10–30%，估省 **246–316 ms**。歷史版第一題相同假設僅約 8–10 ms。 | 保留每次命令的完整快照與 revision。涵蓋作廢、重送、匯入、重設、重啟與 rollback；公平順位有跨題及 3 秒視窗依賴，先保留完整結算。索引隨活動清除，另驗 RSS。 |

## 重現與驗收

- 實際使用 Node v26.7.0、TypeScript 正式 build、每次新建 SQLite；歷史與現行 103 連線均執行 `node e2e/load/socket.mjs --transport websocket --groups 50 --questions 20 --rounds 2 --burst-interval-ms 250 --timeout-ms 5000 --cooldown-seconds 60`（預設值等效）。使用暫存副本的 process.hrtime.bigint／performance.now 與同步巢狀計時，成本表已扣掉子呼叫。診斷插樁、寫出時間戳、GC 與當時系統負載會影響絕對分位數。52 連線補充實驗只報時間窗完整的第一題。負載工具單元測試 `node --test e2e/load/tests/*.test.mjs` 實跑 25 通過、0 失敗。
- 正式驗收先更新 tracker 的收件人規則。現行版本每筆作答追蹤老師、送出者及同組，另逐包檢查其他組／投影未收到作答事件。保留同組 revision 單調、老師全場計數、投影只隨公開活動變更，以及公平判定、作廢與重送的測試。歷史版比對才使用四路。
- 修正前後各跑 WebSocket、純 polling 各 **5 次獨立啟動**，同機同 Node、同設定、不插樁，各自列出五趟。每趟 2,000 筆，單報第一題與全體 ACK p95，兩者均 ≤1,000 ms；三路 6,000 個必要送達逾時 = 0，越權與順位錯誤 = 0。另列 p99、最慢組及每秒 CPU p95，要求每趟 CPU p95 <80%。
- 每趟由原監視器計算暖身與閒置 60 秒的自然 RSS，要求五趟增幅均 <20%。另做 **3 次**同 PID 連跑多個活動的診斷，在每輪關閉後比對 GC 後 heapUsed、外部記憶體、連線與 listener 斜率；強制 GC 的讀值只用於歸因。任何端到端門檻仍未達成時，保留該次結果。
