# 005 公平順位與投影看板：安全覆核紀錄（T033）

日期：2026-11-17。

> **狀態說明（重要）**：本子功能的 T033 原本要求派工給 **GLM worker** 做唯讀安全覆核。本工作階段的執行環境沒有可用的 GLM worker（只能派給影像檢查與公開網路研究兩種子代理），因此以下內容是**主控自我覆核**的結果，**不能冒充 GLM 的獨立覆核**。T033 在 tasks.md 仍保持未勾選，等待有 GLM worker 的階段補做；PR 上的 T034 另一位組員審查同樣待完成。

## 覆核範圍與證據

| 檢查項目 | 方法 | 結果 |
|---|---|---|
| 判定是否只在伺服器 | `answerSettlementService.computeSettlement()` 是唯一判定入口；`answerProjections`、`exportCommands`、`snapshot` 全部呼叫它，前端沒有任何順位推算程式碼 | 通過 |
| 判定結果是否外洩 | `settleAll()` 是純函式，輸入只有已保存的送達資料；回傳值只進入快照投影 | 通過 |
| 投影快照是否真的不含作答資訊 | `projector.test.ts` 直接斷言封包字串**不存在** `"answers"`／`"rank"`／`"cells"`；搶答中的投影快照只有階段、倒數、各組在線與規則 | 通過（封包層級驗證，非只看畫面） |
| 非老師能否取得投影內容 | `broadcaster.ts` 只有 `view === 'projector'` **且**身分為老師時才送投影快照；學生連線維持一般學生快照；`projector.test.ts` 覆蓋此案例 | 通過 |
| 學生可見範圍是否被破壞 | 003 的 `answerVisibility`、`noLeak`、`answerResults` 測試全數未修改語意且通過；open 階段學生快照仍無 `rank`、無其他組作答 | 通過 |
| 揭曉指令的權限與階段 | `commandRouter` 只允許 `teacher`；`projectorCommands` 檢查 `phase === 'closed'`，否則回 `INVALID_PHASE`；冪等不寫入 | 通過 |
| 作廢連鎖重算是否造成資訊外洩 | 重算只改變伺服器內部的推導結果，不新增資料表、不改變作答資料、不產生新的對外欄位 | 通過 |
| log 是否含答案內容 | 新增的例外處理只記 `Fairness settlement reminder failed.` 與既有的事件名稱寫法；log 沒有答案、順位或 token | 通過 |
| CSV 新欄位是否為公式注入風險 | 第 8 欄的值只有 `否`／`是`／`是（改判）` 三種固定字串，不含使用者輸入，並仍經 `escapeCsvField()` | 通過 |
| 資料庫變更 | 只在 `activity` 表新增兩欄（`fair_ranking_enabled`、`revealed_question_count`），皆為 idempotent migration，既有資料預設值不變 | 通過 |
| 密碼與 session | 投影頁沿用既有的老師登入流程（`TeacherLogin`），token 仍只存 sessionStorage、伺服器只存雜湊 | 通過 |

## 值得組員注意的兩個行為（不是漏洞，但有意義）

1. **連鎖重算會改變已廣播的順位**：啟用公平順位時，老師作廢某題的成功組後，該題與後面已判定的題目會重新判定，老師看板的順位會跟著變。這是 D25（2026-11-17 兩組同意）的預期行為。學生端在搶答中看不到順位，所以只影響老師看板與結束後的結果畫面。
2. **學生會看到「本題因公平順位改判」**：這是 FR-011 明列的行為（讓學生知道本場規則與哪些題目被改判），不是資料外洩——學生在結束時本來就能看到每題的搶答成功組別。
