## 資源

| 指標 | 基準值 | 門檻 | 達標 |
|---|---:|---:|---|
| CPU 穩態 | 47.2% | | |
| CPU 每秒 p95 | **100.5%**（max 104.1%，已超過一個核心）| < 80% | ❌ |
| RSS 暖身 → 停止 60 秒後 | 170 MB → 49.6 MB（**-70.8%**）| 增幅 < 20% | ✅（本次是下降）|

> RSS 這個數字在兩台機器上方向相反（另一台是 +45.8%），代表 **RSS 不是穩定指標**，
> 正式比較要同一台機器、同一個 Node 版本、至少 3 次取中位數，並且同時看
> `heapUsed`（Node 行程內部的堆用量）與 RSS（作業系統看到的常駐記憶體）。

## Polling（升級式連線）

同一台機器跑 polling 時，最後的 `activity:close` 指令直接 **TIMEOUT**、整趟失敗
（另一台機器量到逾時 42.9%）。→ 正式環境應強制 `transports: ['websocket']`。
