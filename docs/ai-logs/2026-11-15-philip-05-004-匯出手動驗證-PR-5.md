## 助理

**1. 為什麼每次都要 `npm install`**

其實不一定要，我之前是保險起見才每次都寫。

- `node_modules`（套件資料夾）不會被 git 追蹤，切換分支時它完全不會變動。
- 要裝哪些套件，是看 `package.json` 和 `package-lock.json`。只有新分支改了這兩個檔，才需要重跑 `npm install` 補裝新套件。

我查了一下，`004-export` 跟 `main`、003 比起來，這兩個檔案都沒有改。你之前在 003 已經裝過了，這次**可以跳過 `npm install`**，直接 `npm run build && npm start`。

以後想自己判斷，切換分支後打這行：
```powershell
git diff --stat HEAD@{1} -- package.json package-lock.json
```
沒有任何輸出就不用裝，有列出檔案才需要 `npm install`。

**2. 在外面用手機熱點可以嗎**

可以，而且這次的測試**幾乎不需要網路**。

- **伺服器跑在你的電腦上**，不是靠網路。這次三個角色都開在電腦的 Chrome 分頁，網址是 `localhost:3000`，就算完全沒網路，`npm start` 和這些分頁也都能正常用。
- **需要網路的只有兩件事**：
  - Google Sheets 匯回那段，要上傳檔案到雲端硬碟，伺服器也要從 Google 下載試算表。用熱點就可以。
  - `npm install`。這次不用跑，所以不會用掉流量。

如果之後想讓手機當學生連進來，用熱點也行：電腦連手機熱點，手機開 `http://電腦的IP:3000/student`。IP 一樣用 `ipconfig` 查，熱點網路通常是 `172.20.10.x` 或 `192.168.43.x` 開頭。但要注意，Windows 可能會把熱點當成「公用網路」，防火牆會擋外部連線。手機連不上的話，到 Windows 設定 → 網路和網際網路 → 點這個熱點 → 網路設定檔類型改成「**私人**」。

第四點我指的是，在excel裡面應該可以設定格子的格式，例如讓格寬自動對齊文字、或自動換行等等，這些沒辦法在匯出時設定好嗎?

## 助理

可以設定，但要把檔案格式從 CSV 換成 xlsx 才行。

**CSV 存不了任何格式。**CSV 是純文字，內容只有用逗號隔開的資料。欄寬、自動換行、粗體、凍結窗格這些設定，CSV 裡沒有地方可以放。Excel 打開 CSV 時一律套預設樣式，所以不管匯出程式怎麼寫，這份 CSV 都帶不了格式。

**xlsx 就可以全部設定好。**組員現在匯出學習單用的就是 xlsx，所以作答紀錄也可以匯出成 xlsx，在產生檔案時就設定好：
- 欄寬配合內容長度，「答案」欄限制最大寬度並開啟自動換行；
- 第一列欄位名稱設粗體並凍結，往下捲動時還看得到；
- 「送出時間」設成日期時間格式。

## 使用者

我剛剛要推我的改動時，我的組員剛好推了一個修正版本上來，有一些衝突，於是我現在做了git pull，結果終端機叫我填commit message是為什麼?他預設訊息顯示merge branch欸，但我沒有要merge

## 助理

這是正常的，你沒有做錯。`git pull` 其實是兩個動作合在一起：先把遠端的新 commit **抓下來**（fetch），再跟你本地的 commit **合併**（merge）。

你和組員各自都有對方沒有的新 commit，git 沒辦法直接把其中一邊接到另一邊後面，所以會建立一個「合併 commit」，把兩邊的改動接在一起。叫你填 commit message 就是在幫這個合併 commit 命名。預設的 `Merge branch '004-export' of ...` 就很好，**不用改**。

**怎麼存檔離開：**終端機顯示的畫面通常是 Vim 編輯器（最下面有一排 `~` 或檔名）：
1. 按 **Esc**
2. 輸入 `:wq`（冒號、w、q）
3. 按 **Enter**

如果跳出來的是記事本或 VS Code，就直接存檔再關掉那個視窗。

離開後合併就完成了，接著執行：
```powershell
git log --oneline -3   # 最上面應該是 Merge branch ... 那一筆
git push
```

**順便確認一下：**你剛剛說的「衝突」，是不是 push 被拒絕（訊息裡有 `rejected` 或 `fetch first`）？如果檔案內容真的有衝突，git 會顯示 `CONFLICT`，並停下來要你先處理，不會直接叫你填訊息。現在它直接請你填訊息，代表兩邊的改動 git 都自己合好了。push 之前可以打 `git status`，確認沒有標示「both modified」的檔案。

**以後想避免多一個合併 commit**，可以改用：
```powershell
git pull --rebase
```
這樣會把你的 commit 接到組員的修正後面，歷史紀錄會是一條直線。兩種做法都可以，這次就照現在的合併方式完成就好。

為了讓台灣老師直接辨識，資料庫仍存 UTC，但匯出 CSV 時改成台北時間＋08:00，仍用 ISO 8601 含時區與毫秒，例如 `2026-11-14T22:17:33.100+08:00`，不再輸出 `...Z`。同意同步更新 contract 的時間格式描述嗎？

用同一筆作答來看：

| | CSV 裡的文字 |

**C 的問題：純 CSV 在 Excel 裡沒辦法完全兩全，但可以把影響縮到很小。**

做不到的原因：CSV 只是純文字，沒辦法標記「這一格是文字」。Excel 開啟時，只要看到內容開頭是 `=`、`+`、`-`、`@`，就可能當成公式執行。唯一能擋住的方法是在開頭塞一個別的字元，而 Excel 會把這個字元顯示出來，所以才會看到 `'`。

我建議兩個方向，可以一起做：

1. **只在真的可能是公式時才加 `'`。**純數字像 `-5`、`+3`、`-0.5`，Excel 只會當成數字，不會執行，不需要保護。只有 `=1+1`、`-1+1`、`@SUM(...)` 這類才加 `'`。課堂最常見的就是負數答案，這樣改之後，大部分情況都看不到 `'` 了，安全性也沒有降低。
2. **讓老師主要看 xlsx 版的作答紀錄**（就是 F 項）。xlsx 可以把儲存格明確標成「文字」，本身就不會執行公式，完全不用加符號，還能順便設定欄寬和自動換行。CSV 留給要匯入其他系統的人，維持現在的保護。
