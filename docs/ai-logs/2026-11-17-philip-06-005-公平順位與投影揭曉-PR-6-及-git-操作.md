最乾淨的做法是：直接讓本地分支變成跟 GitHub 上一模一樣。

```powershell
cd <repo>
git status                                   # 確認在 005-fairness-and-extras
git fetch
git log --oneline -1 origin/005-fairness-and-extras   # 應該是 230a443 docs(005): 收錄人工驗證紀錄…
git reset --hard origin/005-fairness-and-extras
```

**注意：**`reset --hard` 會丟掉這個分支上**所有**本地 commit，以及還沒 commit 的修改。這次要丟掉的內容組員都已經收進去了，所以沒關係。做完後可以打開 `docs/verification/005-manual.md` 確認，裡面應該有你 19 步的結果和「介面建議」。

**以後其他情況的做法**（供參考）：

| 情況 | 指令 | 效果 |
|---|---|---|
| 想取消最後一個 commit，但**保留**改過的檔案 | `git reset --soft HEAD~1` | commit 消失，修改還在，可以改完再 commit |
| 想取消最後一個 commit，**連修改一起丟掉** | `git reset --hard HEAD~1` | 回到上一個 commit 的狀態 |
| commit **已經推上 GitHub**，想撤回 | `git revert <commit編號>` | 新增一個「反向」commit 來抵銷它，不會改寫別人已經拿到的歷史 |

已經推上去的 commit 不要用 `reset` 再強制推送，那樣會打亂組員的歷史紀錄。

## 助理

`git fetch` 只做一件事：**把 GitHub 上的最新狀態抓到你電腦上，但不動你的任何檔案。**

你可以把它想成「查看雲端有什麼新東西」：
- 它會把組員新推的 commit（例如剛剛的 `230a443`）下載下來，存在一個叫 `origin/005-fairness-and-extras` 的地方，代表「GitHub 上那個分支目前的樣子」。
- 你正在用的本地分支、資料夾裡的檔案，**完全不會被改到**。

所以 fetch 完之後，你可以先看看組員改了什麼，再決定要怎麼處理：
```powershell
git fetch
git log --oneline -3 origin/005-fairness-and-extras   # 看 GitHub 上最新的 3 個 commit
```

**跟 `git pull` 的差別：**

| 指令 | 做了什麼 |
|---|---|
| `git fetch` | 只下載，不合併；你的檔案不變 |
| `git pull` | `fetch` ＋ 合併到你的分支；你的檔案會更新 |

之前你 `git pull` 時被要求填 commit message，就是因為 pull 裡面「合併」的那一步建立了一個合併 commit。

**這次為什麼要先 fetch：**`git reset --hard origin/005-fairness-and-extras` 的意思是「讓我的分支變成跟 `origin/...` 一樣」。如果沒先 fetch，你電腦裡記的 `origin/...` 可能還是舊的，就會 reset 到過時的版本，看不到組員剛推的 `230a443`。
