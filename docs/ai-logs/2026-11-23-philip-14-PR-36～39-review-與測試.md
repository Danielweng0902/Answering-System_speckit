**合併後會發生什麼：**
- **在 Windows 上（你的電腦）**：Windows 的 git 預設不建立捷徑，會改成建立一個**名叫 `node_modules` 的純文字檔**。這會跟你現有的 `node_modules` 資料夾衝突，pull 或切換分支時可能直接報錯，`npm install` 也可能失敗。

- 任何人 clone 這個專案後跑 `npm ci`，都可能出問題。

**修法：**
```bash
git rm --cached node_modules e2e/node_modules server/node_modules shared/node_modules web/node_modules
```
再把 `.gitignore` 的 `node_modules/` 改成 `node_modules`（拿掉斜線），這樣資料夾和捷徑都會被忽略。

**在組員修好之前，你先不要切到 PR #36 的分支**，以免你本地的 `node_modules` 出問題。這個 PR 只有文件，直接在 GitHub 網頁上看就好。

在組別管理按「改名」，原本的按鈕列會被改名表單取代。被點的那顆按鈕消失了，瀏覽器不知道焦點該放哪，就把它丟回整個頁面的最上面（`<body>`）。結果是：
- **只用鍵盤操作的人**，按 Tab 會從頁首重新開始，要按很多次才能回到原本的位置；

## 組員的修法

1. 按「改名」→ 焦點直接移到改名輸入框，並**選取原本的組名**，直接打字就能覆蓋。

3. 存檔失敗（例如名稱重複）→ 焦點留在輸入框，可以直接修改。

## 使用者

我第四步失敗欸 焦點沒有留在輸入框

## 助理

你找到一個真的 bug，而且是**自動測試抓不到**的那種。

## 原因

存檔時，程式會把改名輸入框設成**停用（disabled）**，避免送出期間被修改：
```tsx
disabled={controlsDisabled}   // 送出中 isSending = true → 輸入框停用
```
在真正的瀏覽器裡，**正在聚焦的元素一旦被停用，瀏覽器就會強制移走焦點**，丟回頁面最上面（`<body>`）。所以流程是：

1. 你按 Enter 存檔 → 輸入框被停用 → **焦點被瀏覽器丟到頁首**
2. 伺服器回覆「名稱重複」→ 輸入框恢復可用，但**沒有程式把焦點放回去**

存檔**成功**的情況沒問題，因為成功後有程式主動把焦點移到「改名」按鈕；**失敗**的情況則是假設焦點「本來就還在」輸入框，所以什麼都沒做。

**那為什麼自動測試會通過？**自動測試跑在 jsdom 這個「模擬瀏覽器」裡，它**不會**在元素停用時移走焦點，所以焦點看起來一直在輸入框。組員做的突變測試也只證明「拿掉修正後測試會失敗」，證明不了測試環境跟真實瀏覽器的行為一致。這就是為什麼需要你人工實測。

## 建議修法

**最簡單的做法：送出時把輸入框改成「唯讀」（readOnly），不要用「停用」（disabled）。**唯讀一樣不能修改內容，但瀏覽器**不會**移走焦點，失敗後焦點自然還在輸入框裡。「儲存」「取消」按鈕可以繼續用停用。

或者，在失敗時主動把焦點放回輸入框，做法跟成功時把焦點還給按鈕一樣。

測試的部分：jsdom 驗證不了這種瀏覽器行為，建議改成檢查「送出期間輸入框沒有被停用」，或者在 Playwright 的 e2e 測試補一個案例，因為 e2e 跑在真的 Chrome 上。
