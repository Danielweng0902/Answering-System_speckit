## Full version（完整版，建議貼在主要說明欄位）

> **Security work**
>
> I maintain a classroom quiz-and-buzz-in system (TypeScript, Express 5, Socket.IO 4, node:sqlite) as a final-year software engineering project at NCU. The codebase is in a public GitHub repository: `[REPO_URL]`.
>
> I conduct authorized, defensive security review of my own codebase, scoped strictly to deployments I control. Work performed so far:
>
> - **Threat modeling.** Defined a trust boundary around the perimeter (firewall/VPN assumed bypassed), then enumerated every unauthenticated HTTP route and every Socket.IO command event, and classified each by the identity it requires and the state it can mutate.
> - **Verification against a local experimental deployment.** Ran all testing on a throwaway server instance — temporary directories, an isolated database, a randomized port, and a dedicated test password — with all artifacts cleaned up afterwards. Confirmed, by direct experiment, that export and import routes correctly reject unauthenticated requests, that role checks hold when teacher commands are replayed with a student identity, that the projector view cannot be forged, and that token comparison is timing-safe.
> - **Finding and fixing real defects.** Each finding was reproduced and then remediated, with a regression test written for every fix. Examples: the student join endpoint had no rate limiting (fixed with token-bucket throttling keyed on a normalized source address); the connection count was bounded only by the OS (fixed with an explicit cap enforced at the handshake layer); session tokens had no expiry and no revocation path (fixed with expiry and explicit revocation semantics); access tokens were persisted in recoverable form (changed to store only a SHA-256 digest); unauthenticated observers could read group membership from the broadcast snapshot (fixed by role-scoped snapshot projection and event routing separation, so the projector no longer receives answer events); password policy enforced no minimum length (strengthened); and unexpected server errors could leak exception messages to clients (suppressed).
> - **Denial-of-service and resource-exhaustion analysis.** Measured unbounded table growth and connection amplification under load, and confirmed that per-request size limits alone do not bound total concurrent memory; mitigated with explicit connection caps and upload concurrency limits, with the fix validated by load test.
> - **Dependency advisory triage.** Ran the ecosystem vulnerability scanner against the project, classified each advisory by reachability and by whether it enters production artifacts, and confirmed that all remaining findings are confined to the lint-time development toolchain while production dependencies report zero advisories. I deliberately did not force-downgrade dependencies across major versions to clear a development-only advisory, and documented the reasoning instead.
>
> All testing was performed only against my own experimental deployment. No third-party system, network, or user data outside my control was accessed, and no work was performed on behalf of a client.
>
> **How I use Claude**
>
> For defensive work on my own systems: building and pressure-testing threat models, reviewing code for authentication, authorization, session handling, and input-validation defects, designing remediations and their regression tests, writing and interpreting verification scripts against my own local experimental deployment, triaging third-party advisories for reachability, and producing the resulting audit and remediation reports. Claude is used as a reviewer and analysis partner throughout this process; every finding I act on is first reproduced empirically against my own deployment.
