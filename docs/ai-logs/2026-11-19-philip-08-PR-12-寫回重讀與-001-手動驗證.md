## 為什麼會寫錯位置

系統是在**匯入那一刻**記下每個答案格的「座標」，例如第 1 題（1）的答案格是 `H5`。寫回時，就照這些座標寫進去。

你在試算表上面新增一列後，所有內容都往下移了一列，原本在 H5 的答案格變成 H6。但系統手上的座標還是 H5，所以答案被寫到新的 H5，也就是錯的位置。

PR #12 的版面比對，就是為了在這種情況下**擋住**寫回。你應該有看到「這份試算表在匯入後被修改過…」，然後按了「**仍要寫回**」？這顆按鈕的意思正是「我知道版面變了，還是照舊座標寫」，所以就寫錯位置了。如果你**沒看到**那個提示就直接寫錯了，那就是 bug，告訴我。

**把試算表救回來：**直接刪掉那一列沒有用，寫錯的答案會跟著一起往上移，還是在錯的位置。請用「檔案」→「版本記錄」→「查看版本記錄」，還原到寫回之前的版本。

## 這次實測發現的兩個問題，都值得寫進 review

**1. 其實可以「自動寫到正確的位置」，程式已經有需要的資料了。**
為了做版面比對，系統寫回前**已經重新讀取並解析了線上試算表**，知道每一題、每一格「現在」在哪個座標。所以只要題號和前綴都對得上、只是位置移動了，就可以直接改用新的座標寫入，不用警告老師，也不會寫錯。只有題目真的對不上（例如題目被刪了、題號改了）才需要停下來。這就是你原本預期的行為。

**2. 訊息裡建議的「重新匯入」，活動結束後其實做不到。**

## 以後怎麼避免

commit 之前先打 `git status`，看第一行寫的是哪個分支：
- `On branch main` → **先**執行 `git switch -c 新分支名稱`，再 commit。
- 已經在新分支上 → 可以 commit。

第一次推新分支時，一定要用 `git push -u origin 分支名稱`。單打 `git push` 會推到目前所在的分支，在 `main` 上就會直接推進 `main`。

## 使用者

我剛剛打git push -u的時候跳錯誤訊息
error: src refspec docs/001-manual-verification does not match any
error: failed to push some refs to 'https://github.com/Danielweng0902/Answering-System_speckit.git'

## 助理

這個錯誤證實了剛剛的推測：**`docs/001-manual-verification` 這個分支從來沒有建立成功**。

`src refspec ... does not match any` 的意思是：「你要我推一個叫 `docs/001-manual-verification` 的本地分支，但我找不到它。」所以實際發生的順序是：
1. `git switch -c docs/001-manual-verification` 沒有執行到，或執行失敗了；
2. `git commit` 在 `main` 上完成；
3. 你打的 `git push` 把 `main` 推了上去，也就是現在 GitHub 上的 `68b67b6`；
4. 之後的 `git push -u origin docs/001-manual-verification` 找不到這個分支，就報錯了。

**這個錯誤本身沒有造成任何影響**，推送失敗代表什麼都沒推。你的紀錄已經在 `main` 上了。

**現在不需要再建分支或推送了。**如果現在才建這個分支，它的內容會跟 `main` 一模一樣，開出來的 PR 沒有任何差異可以看。

確認一下本地狀態：
```powershell
git status
```
應該看到 `On branch main` 和 `Your branch is up to date with 'origin/main'`，而且沒有其他待 commit 的修改，這樣就一切正常。接著照上一則的訊息通知組員就好。
