## 1. CSS 改動是否正確

核心改動正確：`.group`（L133–139）`display: flex` + `justify-content: space-between` 讓 `.groupHeader` 與 `.actions` 並排同一列（PR 實測每列 67px 佐證）；`.renameForm` 的 `flex: 1 1 100%`（L67）在 wrap 容器中是標準的「獨佔一列」寫法，正確。`.actions` 內部繼承的 `flex-wrap: wrap`（L48）**不會**讓按鈕換行——`.actions` 不可壓縮（`flex: 0 0 auto`）、寬度由內容決定，兩顆按鈕（「改名」「刪除」）合計約 176px，遠小於最小內容寬（390px 視窗 − 32px padding ≈ 358px）。但有一個文件層面的問題：

**發現 1（低嚴重度）— `.actions` 註解過度承諾，換行仍可能發生**
- **檔案與行號**：[GroupManager.module.css:53-60](/Users/Pig0902/Answering-System_speckit/web/src/features/teacher/GroupManager.module.css#L53)（註解 L53–56、規則 L57–60）
- **問題**：註解說「按鈕列不可被壓縮**或換行**」，但 `flex: 0 0 auto` 只防止壓縮。`.group` 是 `flex-wrap: wrap`，當組名（以 max-content 計，不是收縮後寬度）＋按鈕列超出容器寬時，`.actions` 仍會整個換到第二列，之後靠 `margin-inline-start: auto` 置右。
- **為什麼是問題**：窄視窗下掉到第二列、靠右，其實是合理的降級，不是 bug；但註解把「不會換行」寫成保證，日後有人回報「按鈕掉到下一列」時，這行註解會誤導維護者以為那是不可能狀態。另外 `margin-inline-start: auto` 與 `space-between` 在單列時是重複的（auto margin 吃光剩餘空間後 space-between 無空間可分），真正的差別只在換行後置右——若是刻意設計，值得註明。
- **建議**：註解改寫為「不可被壓縮；空間不足時整列換行到下一行、靠右」的準確描述。
