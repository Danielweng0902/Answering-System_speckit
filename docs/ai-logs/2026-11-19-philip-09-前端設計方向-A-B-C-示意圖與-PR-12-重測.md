## 助理

我整理了三類可以直接用的資源，加上三個視覺方向的提案。先講結論：**不要找現成的 UI 模板或元件庫來套**，例如 shadcn、MUI、Tailwind UI 那種範本。AI 生成的介面之所以有「AI 味」，大多就是因為這些預設外觀。比較有效的做法是：用一個「防 AI 味」的 skill 約束 AI，再搭配你們自己定的字體和配色。

## 一、可以直接裝的 skill（讓 AI 照規矩做）

**1. Anthropic 官方的 `frontend-design`**
專門用來讓 AI 做出有辨識度、可上線的前端介面，避開千篇一律的「AI slop」美感。它會明確警告不要用陳腔濫調的做法：紫色漸層、可預測的版面、制式元件，以及一看就是 AI 隨手產出的字體搭配，也會要求避開 Inter、Roboto、Arial 和系統字體。在 Claude Code 可以用 `npx skills add anthropics/skills` 安裝。

**2. Impeccable（進階版，更適合你這個「審畫面」的角色）**
它是 Paul Bakaus 做的開源 Claude Code skill，專門處理 AI 生成前端的「AI slop」問題，提供 20 個可操作的指令（/audit、/polish、/critique 等）、7 份設計參考文件，以及一份反模式清單，明確告訴 AI 不要生成什麼。對你特別有用的是，它附帶一個獨立的命令列工具，不需要 AI 也能檢查反模式：`npx impeccable detect src/` 掃描整個資料夾。你審 PR 畫面時，可以先跑一次，用工具挑出問題，比較不會只是主觀感覺。版本更新很快，安裝前先到 impeccable.style 確認目前的安裝方式。

**建議做法**：把其中一個 skill 放進 repo 的 `.claude/skills/`，組員的 agent 實作畫面時就會自動讀到。但 skill 只負責「避開壞習慣」，**長什麼樣子還是要靠你們自己的 `DESIGN.md` 決定**。

## 二、免費、可商用的繁中字體（最能擺脫 AI 味的一步）

AI 預設的字體幾乎都是系統黑體，換掉字體，整體氣質就會差很多。

| 字體 | 特色 | 適合用在 |
|---|---|---|
| **霞鶩文楷 TC** | 教科書風格的字體，融合仿宋與楷書的特點，像手寫但很工整 | 題目、標題，很有「學習單」的感覺 |
| **jf open 粉圓** | justfont 出品，字體架構比其他現代圓體稍微緊縮，看起來有點特別，又不會太搶眼，台灣慣用字型 | 學生手機上的按鈕、內文，親切不呆板 |
| **DSEG7** | 重現熟悉的七段顯示器樣式，提供數字、精簡拉丁字母和符號，有三種字重，就是電子計分板的數字 | **倒數計時、順位數字**，投影上很有搶答節目感 |

這三款都是 OFL 開源授權，可以免費商用。要注意的是中文字體檔案很大（好幾 MB），學生用教室 Wi-Fi 連線時會載入很慢。霞鶩文楷 TC 和 DSEG 都可以從 Fontsource 安裝，它會把字體切成小塊、只載入用到的字；粉圓要自己做子集化，只保留用到的字。

## 三、三個視覺方向提案

`KICKOFF-PLAN.md` 已經建議從「黑板／計分板／紙本學習單」找方向，我把它們具體化：

**A. 紙本學習單＋紅筆批改（我最推薦）**
- 理由：你們的系統本身就是匯入 Guided Notes 學習單，概念最一致，別組也很難撞。
- 米白紙色背景、淡淡的格線，題號用大字放在左側邊欄。
- 「搶答成功」用**紅筆圈起來**的效果，「已送出」用藍筆打勾，「改判」用紅筆劃線修改。
- 題目用霞鶩文楷，數字用一般字體。

**B. 搶答節目計分板**
- 黑底、琥珀色 LED，倒數和順位用 DSEG7。
- 投影「揭曉」時做翻牌動畫（像車站的翻牌時刻表）。
- 投影上效果最強，但學生手機上滿版黑底比較難做得好看。

**C. 黑板粉筆**
- 墨綠黑板底、粉筆白字、粉筆黃當強調色。
- 風險是很容易做成「俗氣的仿真風格」，要很克制：不要放黑板紋理圖片，只用顏色和字體表現。

**混搭也可以**：以 A 為主，只在**投影頁的倒數**借用 B 的 DSEG 數字。但最多借一個元素，概念太雜反而像拼貼。

## 優點

1. **學生的答案不會公開。**這點組員沒提到，但我覺得是最重要的：寫回之後，學生的答案就在那份試算表裡。現在因為規定要開「知道連結者可檢視」，**任何拿到網址的人都看得到全班答案**。改了之後，試算表可以維持「限制」。
2. **老師少一步設定**，也少一個容易忘記的步驟。
3. **寫回前的版面比對變可靠。**比對要先讀取線上試算表，現在是靠公開連結讀。老師一關掉公開連結，就會一直出現「無法確認試算表有沒有被改過」，只能按「仍要寫回」，而這正是你實測時寫錯格的那條路徑。改用服務帳號讀，比對幾乎都能成功。之後如果要做「版面位移時自動改用新座標」，也會穩很多。
4. **讀和寫用同一個身分**，權限錯誤比較單純，只要檢查「有沒有共用給服務帳號」。

## 缺點和成本

1. **要改 002 的約定（FR-002）**，兩組都要同意。但如果做成「**有服務帳號就用它讀，讀不到再退回公開連結**」，原本只開公開連結的用法還是能用，這就只是「**多一種方式**」，不是推翻原本的規則，比較容易取得同意。
2. **要維護兩條讀取路徑**，測試和錯誤情況會變多。例如「有設定服務帳號，但這份試算表沒共用給它」時，要退回公開連結，還是直接告訴老師「請共用給服務帳號」？這要先決定好。
3. **老師要知道服務帳號的信箱才能共用。**現在這個信箱只寫在 `.env` 裡，介面上應該顯示出來，旁邊加一個複製按鈕。
4. **時間。**剩沒幾天，前端設計也還沒動工。

## 為什麼做得到

## 有幾個地方要先知道

- **中文字體很大**：霞鶩文楷和思源宋體的完整檔案都有好幾 MB。用 `@fontsource` 的 npm 套件安裝，它會把字體切成小塊、只載入用到的字，而且字體檔放在你們自己的伺服器上，教室斷網也能用。
- **橫線是裝飾**：內容長短會變，不可能保證每行字都剛好壓在線上。橫線就當作淡淡的紙張背景，不追求對齊。
- **「正」字記號的第 4 筆沒有現成的字**：一、丅、下、正這幾個階段有字可用，但「正」少最後一筆的樣子沒有標準字元。要用 SVG 畫五條線，不難，但要寫進規格裡。
- **老師頁面還沒有示意圖**：我只做了學生手機和投影。老師頁面的東西最多（組別管理、匯入、作答看板、寫回），開工前最好也先畫一張。
- 紅筆圈、劃線、題號放在左側邊欄這幾個效果，需要小幅調整元件的 HTML 結構，不只是改 CSS。
