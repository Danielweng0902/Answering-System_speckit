### F-01　題組題目「先填後面的空格」時，重新整理後未送出草稿遺失（已重現）

| 項目 | 內容 |
|---|---|
| 嚴重度 | **Medium** |
| 對應 | FR-027（未送出內容重新整理後仍在／MUST 清除不帶到下活動）、AC-003-28、spec.md Edge Cases、README.md 新增敘述「學生尚未送出的草稿只存在自己的裝置上，重新整理不會不見」 |
| 位置 | [web/src/features/student/AnswerArea.tsx:84-86](<repo>/web/src/features/student/AnswerArea.tsx:84)、[web/src/features/student/answerDrafts.ts:27-35](<repo>/web/src/features/student/answerDrafts.ts:27) |

**原因**
`updateAnswer` 用 `answers[blankIndex] = value` 直接以索引賦值；當學生先在題組第 2 格輸入時，陣列長度 1→2、index 0 成為 **hole**，spread 後變成 `undefined`。`JSON.stringify` 把 hole 序列化成 `null` → localStorage 存成 `{"1":[null,"乙"]}`。重新整理後 `parseStoredDrafts` 的防護條件 `answers.every((a) => typeof a === 'string')` 對 `null` 不成立，於是 **整題草稿被丟棄**（不是只丟那一格）。

**重現步驟（已實際執行，使用工作區真實模組 `answerDrafts.ts`）**
1. 開啟搶答中、匯入 `fixtures/guided-notes/02-official-group.xlsx`（第 1、2 題各 2 格）。
2. 學生在第 1 題的「（2）」輸入框先輸入 `乙`（**不要**碰「（1）」）。
3. F5 重新整理。
4. 實際結果：「（2）」輸入框變成空值，該題草稿消失。

**Expected**：重新整理後「（2）」仍顯示 `乙`。
**Actual**：`localStorage` 內 `{"1":[null,"乙"]}` → 讀回 `{}` → 輸入框空白。

執行證據（腳本置於 `/private/var/.../T/opencode/003-test-review/repro-draft.ts`，僅 import 工作區既有程式碼，未改動工作區）：
```
[A] 單題只填第 1 格      儲存 {"1":["甲"]}      讀回 {"1":["甲"]}
[B] 題組先填第 2 格      儲存 {"1":[null,"乙"]} 讀回 {}          ← 草稿遺失
[C] 題組依序填 1→2 格    儲存 {"1":["甲","乙"]} 讀回 {"1":["甲","乙"]}
```

**影響範圍**：只影響題組題目（多空格）且「先填後面的空格」的使用者；單空格題不受影響；送出的資料不受影響（送出前的前端檢查會擋下未填空格，送出 payload 仍合法）。

**建議最小修正（二選一）**
- `AnswerArea.tsx:84` 改為依題目空格數補齊空字串：
  `const answers = question.blanks.map((_b, i) => current[question.number]?.[i] ?? '');` 再 `answers[blankIndex] = value;`
- 或 `answerDrafts.ts` 的 `parseStoredDrafts` 對非字串元素改成 `''`（保留整題草稿）而不是 `continue` 丟棄整題。

**建議最小能失敗的回歸測試**（`web/tests/AnswerArea.test.tsx` 新增案例，現在會失敗）
```tsx

  render(<AnswerArea snapshot={groupSnapshot()} />);

    target: { value: '乙' },
  });
  cleanup();                                   // 模擬重新整理
  render(<AnswerArea snapshot={groupSnapshot()} />);
  expect(
```

- **revision／hydrate**：teacher=`activity.revision+answerEventCount`、student=`activity.revision+本組 answerRevision`、guest=`activity.revision`；reset 不歸零以維持單調，前端 `useSnapshot` 的 role 變更重設基準邏輯一致。
