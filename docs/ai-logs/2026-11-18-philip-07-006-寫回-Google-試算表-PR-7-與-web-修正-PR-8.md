## PR #8：表單和無障礙修正

**你問的 `role="switch"`：公平順位用 OK，倒數建議改回 checkbox。**

依照 W3C 的無障礙指引（ARIA APG）：
- **switch（開關）**用在「切換後**立刻生效**」的設定。公平順位的開關一切換就立刻送出指令，用 switch 正確。
- **checkbox（勾選框）**用在「先選好，按別的按鈕才生效」的選項。「設定倒數」勾了之後要填秒數、再按「開啟搶答」才會生效，比較適合維持 checkbox。

另外，從設計角度看：加了 `role="switch"` 後，螢幕閱讀器會念「開關」，但畫面上還是方形勾選框，看到的和聽到的不一致。既然公平順位要用 switch，建議之後把它的**外觀也做成滑動開關**，這可以放進 `DESIGN.md`。

其他修改：
- ✅ 送出失敗時，焦點移到第一個沒填的欄位，很好。
- ✅ 密碼欄設為必填，沒問題。
- ⚠️ **答案上限 200 字會「默默截斷」。**加了 `maxLength` 之後，學生貼上 201 字時，瀏覽器會直接截成 200 字，**不會有任何提示**。003 測過的「最多 200 字」錯誤訊息也不會再出現。學生可能沒發現答案被截掉。建議在輸入框旁邊顯示字數，例如「123／200」。所以這點其實有一點改到使用者看得到的行為，不完全是「沒改行為規格」。
- 勾選框的強調色用的是 `--color-focus`（焦點顏色）。這屬於設計決定，等 `DESIGN.md` 定案後再統一就好。

## 助理

錯誤訊息是「暫時無法寫入」，但程式裡這個訊息其實包了好幾種不同的原因，不一定是暫時性的問題。依可能性排，最常見的是這兩種：

**原因 1（最可能）：那份檔案還是 xlsx，不是真正的 Google 試算表**

打開線上試算表，看兩個地方：
- 標題旁邊有沒有一個 **`.XLSX`** 的小標籤？

只要有其中一個，就代表 Google 只是「用試算表介面打開 xlsx 檔」。這種檔案可以讀取，所以匯入成功了，但 API **不允許寫入**。

你剛剛先測 PR #7，伺服器跑的是 `006-guided-notes-writeback` 分支。我查了一下，這個分支是在 PR #8 合併**之前**開的，裡面**完全沒有** Enter 的處理，也沒有字數顯示。所以在那個版本裡按 Enter，本來就不會有任何反應，跟 iPhone 或輸入法都無關。

**先看一個地方就能確認：**手機上的答案輸入框旁邊，有沒有出現 `0／200` 這種字數？

- **沒有字數** → 確定是版本問題。照下面切到 `main` 重測：
  ```powershell
  # 先在跑伺服器的視窗按 Ctrl+C 停止
  cd <repo>
  git checkout main
  git pull
  npm run build
  npm start
  ```
  手機重新整理頁面，看到字數之後再試一次 Enter。如果還是沒出現字數，可能是瀏覽器用了舊的快取，把 Safari 分頁關掉重開。

- **有字數，但 Enter 還是沒反應** → 那就是 iPhone 真的有問題。iPhone 的 Safari 有一些已知的怪異行為：它可能把鍵盤上的 Enter 回報成「輸入法正在選字」的訊號（`keyCode 229`），程式以為你在選字，就忽略了這次 Enter。這種情況要回報給組員。比較穩的修法是把每一題包成一個 `<form>` 表單，讓 iPhone 鍵盤的 Enter 鍵直接觸發瀏覽器原生的「送出表單」：瀏覽器本身就不會在選字時送出，也不用自己判斷輸入法。

另外，**電腦上按 Enter 有反應嗎？**如果電腦也沒反應，就幾乎可以確定是版本問題。

確認是哪一種情況後告訴我。如果是 iPhone 真的有問題，我幫你寫回報給組員的留言。
