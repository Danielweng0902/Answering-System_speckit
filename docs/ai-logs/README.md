# AI 對話紀錄（繳交用）

> 這是本專案與 AI 代理的**對話紀錄**，供課程繳交作業使用
> （constitution：「與 AI 代理的對話紀錄 MUST 保存，供繳交使用；
> 保存前 MUST 檢查不含機敏資料」）。

## 這些檔案是什麼

每個檔案是一個 AI 工作階段（session）的**對話本身**：

- `## 使用者` —— 組員的提問與指示
- `## 助理` —— AI 的文字回覆

檔名格式：`<日期>-<session 標題>.md`。檔頭有 session id、日期、模型與輪次。

### 兩個來源

| 來源                        | 檔名開頭               | 產出方式                                                | 內容                                                            |
| --------------------------- | ---------------------- | ------------------------------------------------------- | --------------------------------------------------------------- |
| **本 thread（SpecKit 組）** | `2026-11-…`            | `scripts/export-ai-logs.mjs` 匯出 opencode session      | 規格、實作、審查、壓測、資安審計等 73 個工作階段                |
| **Philip（組員）**          | `2026-11-…-philip-NN-` | `scripts/import-ai-logs.mjs` 匯入他用其他工具整理的紀錄 | 他自己的測試與 review 對話 15 個階段（2026-11-09 → 2026-11-23） |

Philip 的紀錄涵蓋：前端設計方向的決定（避免 AI 千篇一律的風格）、002～006 的人工驗證過程、
前端 UI 分工討論、PR #2～#39 的審查與實機測試、以及 i18n 與效能重構的驗證 ——
這些是本 thread 看不到的面向，必須一併收錄才算完整的對話紀錄。

目前合計 **88 個 session 檔**（約 1.9 MB）。

## 怎麼產生的

```bash
# 本機 opencode 的 session
node scripts/export-ai-logs.mjs          # 匯出本專案全部 session
node scripts/export-ai-logs.mjs --list   # 只列出 session

# 組員用其他工具整理的紀錄
node scripts/import-ai-logs.mjs <來源資料夾>
```

兩個工具**共用同一套遮蔽規則**（`scripts/lib/redact.mjs`），行為一致。

流程：

1. `opencode session export <session-id>` 取得原始紀錄（**未遮蔽**）。
2. 只保留「對話本身」—— 工具呼叫與推理內容不收錄（那是執行細節，而且體積大 30 倍）。
3. 機敏值換成佔位符（`<redacted>`、`<redacted-private-key>`、`<redacted-bearer-token>` 等），
   **本機絕對路徑也一併換掉**（見下）。
4. 產出後用 `scripts/scan-ai-log-secrets.mjs` 掃描確認乾淨。
5. 暫存的原始匯出檔一律刪除，不留在磁碟上。

## 為什麼不用 `opencode session export --sanitize`

那個旗標會把**所有**訊息內容（含組員的提問與 AI 的回覆）換成 `[redacted:…]`，
匯出來的紀錄沒有閱讀價值。本目錄改為**保留對話、只替換機敏值**。

## 機敏資料的處理

已實測驗證（2026-11-24）：

| 檔案                               | 掃描結果                                  |
| ---------------------------------- | ----------------------------------------- |
| 未遮蔽的原始匯出（單一 session）   | **548 處**（含 7 處 Google 服務帳號私鑰） |
| 本目錄的匯出結果（全部 73 個檔案） | **0 處**                                  |

替換規則集中在 `scripts/lib/redact.mjs` 的 `REDACTIONS`：服務帳號私鑰、Bearer token、
JWT、GitHub token、AWS key、密碼／憑證關鍵字後的值、看起來像憑證的環境變數指派，
以及本專案用過的測試密碼值。

**掃描器直接引用同一套規則**（`scripts/scan-ai-log-secrets.mjs`），所以掃描結果就是
「實際套用遮蔽時會被改動的地方」—— 不會出現「掃描報了但其實沒問題」或反過來的落差。
（2026-11-23 就發生過：兩套實作各自演化，掃描器把 `SHEET_URL = "貼上你的試算表網址"`
這種說明文字報成機敏。）

掃描器本身也驗證過有效（對未遮蔽的原始匯出能抓到 548 處、對 Philip 的原始紀錄能抓到 15 處），
不是「壞掉所以沒掃到」。遮蔽規則的測試在 `scripts/tests/redact.test.mjs`（6 項，已接進
`npm run check`）。

## 絕對路徑的遮蔽

2026-11-23 的 review 指出：紀錄裡有大量 `/Users/<使用者名稱>/…` 絕對路徑。repo 是公開的，
不適合帶著本機使用者名稱。匯出工具現在會把：

| 原始                                            | 匯出後             |
| ----------------------------------------------- | ------------------ |
| `/Users/<名稱>/Answering-System_speckit/docs/…` | `<repo>/docs/…`    |
| `/Users/<名稱>/Desktop/…`                       | `<home>/Desktop/…` |
| `C:\Users\<名稱>\…`                             | `<home>\…`         |

相對路徑（`docs/…`）不動。目前 73 個匯出檔中：`<repo>` 出現 388 處、`<home>/` 162 處、
殘留的 `/Users/` **0 處**。

## 檔名撞名

`opencode session list` 的標題與匯出檔的 `info.title` **不一定相同**，而且同一個標題可以出現在
多個 session 上（例如兩次不同的「004-t027-glm-安全覆核」）。所以檔名唯一性必須以
「實際要寫的檔名」為準來檢查 —— 匯出工具會偵測撞名並加上序號（`-2`、`-3`），
避免後一個 session 覆蓋前一個而讓紀錄遺失。

（2026-11-24 修正：先前版本只檢查 `session list` 的標題，實際撞名的是 3 個 session，
它們的對話紀錄被覆蓋而沒有進版控。）

## 匯出時被略過的內容

- **工具呼叫的輸入與輸出**（shell 指令、檔案內容、API 回應）
- **推理內容**
- 閒置與系統訊息

理由：這些不是「對話」，而且會帶入大量非對話的檔案內容（增加機敏資料的暴露面）。
