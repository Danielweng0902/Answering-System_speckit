## 1. 需求編號

核心（必做）

| ID | 需求 |
|---|---|
| C1 | 有老師與學生兩種使用者 |
| C2 | 老師匯入 Guided Notes；題數與原檔一致；以題號表示題目即可 |
| C3 | 老師開啟、結束搶答 |
| C4 | 老師檢視搶答中的作答狀況與搶答結果 |
| C5 | 老師把搶答成功組別的答案匯出回原 Guided Notes 的填空格 |

| C10 | 最快送出的組別為搶答成功 |

## 2. 決策

| # | 決策 | 內容 | 狀態 |
|---|---|---|---|
| D1 | 搶答方式 | **整場開放**：老師開啟後所有題目同時可作答，每題各自比誰最快；老師結束（或倒數結束）後才公布結果 | Default（已詢問助教草稿，未送出） |
| D2 | 活動階段 | `準備中` → `搶答中` → `已結束`，只能往前，由老師操作（倒數結束視同老師結束） | Default |
| D3 | 學生身分 | 以組為單位進場：選擇組別後進入；同組可多人同時在線 | Default |
| D4 | 誰能送出 | 同組任一人都能送出；某題送出後，全組該題鎖定並同步顯示「已送出」 | Default |
| D5 | 能否修改 | 已送出的答案不能修改 | Default |
| D6 | 一題多組送出 | 每組每題可送一次；全部記錄並依伺服器收到的順序排順位；第 1 順位為搶答成功 | Default |
| D7 | 搶答中學生可見範圍 | 只看到自己組的答案與送出狀態；看不到其他組是否已送出、也看不到某題是否已被搶走 | Default |
| D8 | 結束後學生可見範圍 | 每題的搶答成功組別與其答案，以及自己組在各題的順位 | Default |
| D9 | 老師可見範圍 | 搶答中即時看到每題各組的送出狀態、答案與順位 | Default |
| D10 | 題組 | 一個題組算一題：所有空格都填了才能送出，整題一起比順位 | Default |
| D11 | 匯入 | 貼 Google Sheets 連結（知道連結者可檢視）或上傳 xlsx；依表頭「題號／題目／作答」與合併範圍辨識題目與空格；匯入後顯示題數讓老師確認 | Default |
| D12 | 匯出回 Guided Notes | 老師的學習單存在自己的雲端 Google Sheets，系統須**直接對那份線上試算表讀寫**：讀取時連線取得最新內容（已實作），寫回時把搶答成功組別的答案直接寫入對應的填空格，不以「下載成 xlsx 再由老師手動覆蓋」作為主要流程。答案寫入仍是純文字、不得被試算表當成公式；前綴與答案的版面規則同 v0.5（分離時答案寫右側獨立格、合併填答區保留「前綴＋答案」）。匯入來源是上傳的 xlsx 時沒有雲端目標，這條路徑維持下載。寫入需要編輯權限，以服務帳號共用方式認證（006 實作） | Confirmed（2026-11-17 助教說明；實作方式由兩組定案） |
| D13 | CSV 欄位 | `題號, 空格序, 組別, 答案, 順位, 是否搶答成功, 送出時間, 公平順位`；UTF-8（含 BOM，Excel 可直接開）。最後一欄標示本場是否啟用公平順位（`是`／`否`）；啟用時，若該題的搶答成功者不是最先送達者（因公平順位改判），該題的列標為 `是（改判）` | Confirmed（2026-11-17 兩組同意；第 8 欄為 005 新增） |
| D14 | 公平順位 | 老師在「準備中」選擇是否啟用，**預設不啟用**（不啟用時一律最先送達者搶答成功）。啟用時：某題第一個答案送達後 3 秒內送達的組別視為同一批；同一批中，已判定題目的搶答成功題數最少的組別優先，題數相同再比送達順序。題目依第一個答案送達的先後判定。結果與匯出須標示是否啟用；老師作廢造成重判時依 D25 | Confirmed（2026-11-17 兩組同意） |
| D15 | 倒數計時 | 老師開啟時可選擇是否設定時間；時間到自動結束 | Default |
| D16 | 投影看板 | 老師可開啟適合投影的畫面。搶答中只顯示階段、倒數、各組是否在線，**不顯示任何作答資訊（含送出數量）**，以符合 C9。結束後老師可逐題揭曉或全部揭曉搶答成功組別與答案；逐題揭曉依**題號順序**，全部揭曉後顯示各組搶答成功的題數 | Confirmed（2026-11-17 兩組同意） |
| D17 | 組別建立 | 老師在準備階段設定組數與組名 | Default |
| D18 | 老師身分 | 老師需輸入密碼才能進入老師端；密碼由環境變數設定。登入狀態以瀏覽器的 **HttpOnly cookie** 保存（頁面 JavaScript 讀不到憑證），cookie 屬性為 **`HttpOnly; SameSite=Strict; Path=/`、不設 `Max-Age`（工作階段 cookie）、不設 `Secure`**（正式環境走 HTTPS 時再加 `Secure`）；重新整理後仍有效；老師可隨時**登出**（登入狀態立即失效，cookie 以 `Max-Age=0` 清除）；**伺服器重新啟動後老師的登入狀態失效，須重新登入**。未登入或登入狀態已失效時呼叫老師端點，一律回 **401 `TEACHER_AUTH_REQUIRED`**（已登入但不是老師回 403 `FORBIDDEN`） | Confirmed（2026-11-22 兩組同意；cookie 屬性 2026-11-23 統一為 Strict） |
| D19 | 重設活動 | 老師可在「已結束」後重設活動回到「準備中」（需再次確認）；組別保留，本次活動的作答資料清空，**該活動學生的進場狀態一併作廢**（老師的登入狀態保留）：學生的 token 立即失效，**已連線的學生也會被通知（`session:invalid`，原因為「活動已重設」）並回到選組頁**（組別保留，重新點一下即可進場）；**重設當下不在線的學生，在重新連線時也會收到通知並回到選組頁**（原因說明為「進場狀態已失效」；失效原因在 session 被作廢後已無法分辨） | Confirmed（2026-11-25 兩組同意）；**2026-11-27 補充（重連時也通知）⏳ 待 OpenSpec 組確認**（提案見 [`REPLY-2026-11-27.md`](./REPLY-2026-11-27.md)） |
| D20 | 數量限制 | 組名 1–30 字元且不重複；最多 **100 組**；倒數時間 10 秒至 60 分鐘 | Confirmed（2026-11-22 兩組同意：原 50 組改為 100 組） |
| D22 | 題目敘述 | 匯入時若有題目敘述則一併讀取，作答區在題號旁顯示；沒有也不影響 | Default |
| D23 | 答案規則 | 每個空格的答案去除前後空白後 1–200 字元；不判斷對錯 | Default |
| D24 | 老師作廢 | 搶答中，老師可作廢某組某題的作答，該組即可重新送出；重送的順位排該題現有號碼之後，其他組順位不變；被作廢的作答保留紀錄（顯示已作廢）但不計入搶答成功、進度與結果；只能在搶答中作廢；作廢事件只送老師與該組 | Confirmed（2026-11-13 兩組同意） |
| D21 | 換組與重連 | 學生只能在「準備中」換組；重新整理或斷線重連後回到原組別與目前階段 | Default |
| D25 | 公平順位下的作廢重判 | 啟用公平順位時，老師作廢某題的搶答成功組後，該題以**剩餘有效作答**重新判定；因各組搶答成功題數改變，**後面已判定的題目也依新的成功題數一併重新判定**（不啟用公平順位時維持先到先得，只有被作廢的組別可重送） | Confirmed（2026-11-17 兩組同意） |

## 3. 共同驗收情境

每個子功能的規格會補上自己的 `AC-<子功能>-<序號>`。以下是整體流程的最低共同標準：

| ID | 情境 | 預期結果 | 需求 |
|---|---|---|---|
| AC-000-01 | 老師匯入官方單題範本 | 顯示 6 題 | C2 |
| AC-000-02 | 老師匯入官方題組範本 | 顯示 4 題，其中 2 題為題組（各 2 個空格） | C2, E1 |
| AC-000-03 | 老師匯入欄位位置不同的學習單 | 題數與空格正確，不因位置不同而出錯 | C2 |
| AC-000-04 | 老師開啟搶答 | 所有已進場的學生畫面在 2 秒內變成可作答 | C3, C6, C11 |
| AC-000-05 | A 組先送出第 1 題，B 組後送出 | 老師端看到 A 為第 1 順位、B 為第 2 順位；A、B 互相看不到對方狀態 | C4, C7, C9, C10 |
| AC-000-06 | 搶答中學生重新整理頁面 | 回到同一階段，自己組已送出的答案仍在 | C11 |
| AC-000-07 | 老師結束搶答 | 所有學生畫面在 2 秒內顯示結果；之後不能再送出 | C3, C8, C11 |
| AC-000-08 | 老師匯出回 Guided Notes | 每題填空格內是搶答成功組別的答案；沒有人作答的題目保持空白 | C5 |
| AC-000-09 | 老師匯出 CSV | 內容與老師端看到的順位一致 | E2 |
