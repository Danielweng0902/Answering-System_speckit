# Feature Contract（兩小組共同約定）

> 版本 v0.2 草稿｜2026-11-11｜SpecKit 組提出，**尚待 OpenSpec 組確認**
> 用途：課程規定兩小組的系統功能必須一致。這份文件只寫「使用者看得到的行為」，不寫技術選型。
> 狀態：`Confirmed` 兩組都同意／`Default` SpecKit 組先採用，等對方確認／`Open` 未決。
> 修改方式：行為有變動就改這份文件，兩組各至少一人同意後才生效。

## 1. 需求編號

核心（必做）

| ID | 需求 |
|---|---|
| C1 | 有老師與學生兩種使用者 |
| C2 | 老師匯入 Guided Notes；題數與原檔一致；以題號表示題目即可 |
| C3 | 老師開啟、結束搶答 |
| C4 | 老師檢視搶答中的作答狀況與搶答結果 |
| C5 | 老師把搶答成功組別的答案匯出回原 Guided Notes 的填空格 |
| C6 | 學生在搶答開始後作答 |
| C7 | 學生以組別為單位送出答案 |
| C8 | 學生在搶答結束後檢視結果 |
| C9 | 搶答結束前，學生看不到其他組的作答狀況 |
| C10 | 最快送出的組別為搶答成功 |
| C11 | 所有使用者的活動階段保持同步 |

額外（兩組都做）

| ID | 需求 | 狀態 |
|---|---|---|
| E1 | 題組匯入：同一題號下的多個空格必須同時送出 | Default |
| E2 | 活動結果匯出 CSV（題號、組別答案、搶答順位） | Default |
| E3 | 公平順位機制，鼓勵還沒搶答成功的組別 | Default |
| E4 | 倒數計時（時間到自動結束）與投影看板 | Default |

## 2. 決策

| # | 決策 | 內容 | 狀態 |
|---|---|---|---|
| D1 | 搶答方式 | **整場開放**：老師開啟後所有題目同時可作答，每題各自比誰最快；老師結束（或倒數結束）後才公布結果 | Default（已詢問助教草稿，未送出） |
| D2 | 活動階段 | `準備中` → `搶答中` → `已結束`，只能往前，由老師操作（倒數結束視同老師結束） | Default |
| D3 | 學生身分 | 以組為單位進場：選擇組別後進入；同組可多人同時在線 | Default |
| D4 | 誰能送出 | 同組任一人都能送出；某題送出後，全組該題鎖定並同步顯示「已送出」 | Default |
| D5 | 能否修改 | 已送出的答案不能修改 | Default |
| D6 | 一題多組送出 | 每組每題可送一次；全部記錄並依伺服器收到的順序排順位；第 1 順位為搶答成功 | Default |
| D7 | 搶答中學生可見範圍 | 只看到自己組的答案與送出狀態；看不到其他組是否已送出、也看不到某題是否已被搶走 | Default |
| D8 | 結束後學生可見範圍 | 每題的搶答成功組別與其答案，以及自己組在各題的順位 | Default |
| D9 | 老師可見範圍 | 搶答中即時看到每題各組的送出狀態、答案與順位 | Default |
| D10 | 題組 | 一個題組算一題：所有空格都填了才能送出，整題一起比順位 | Default |
| D11 | 匯入 | 貼 Google Sheets 連結（知道連結者可檢視）或上傳 xlsx；依表頭「題號／題目／作答」與合併範圍辨識題目與空格；匯入後顯示題數讓老師確認 | Default |
| D12 | 匯出回 Guided Notes | 產生與原檔相同格式、已在各題填空格寫入搶答成功答案的 xlsx；題組保留「（1）」等前綴，答案接在後面。直接寫回雲端試算表列為之後的擴充 | Default（待助教回覆） |
| D13 | CSV 欄位 | `題號, 空格序, 組別, 答案, 順位, 是否搶答成功, 送出時間`；UTF-8（含 BOM，Excel 可直接開） | Default |
| D14 | 公平順位 | 老師在「準備中」選擇是否啟用，**預設不啟用**（不啟用時一律最先送達者搶答成功）。啟用時：某題第一個答案送達後 3 秒內送達的組別視為同一批；同一批中，已判定題目的搶答成功題數最少的組別優先，題數相同再比送達順序。題目依第一個答案送達的先後判定，已判定的不再改變。結果與匯出須標示是否啟用 | Default |
| D15 | 倒數計時 | 老師開啟時可選擇是否設定時間；時間到自動結束 | Default |
| D16 | 投影看板 | 老師可開啟適合投影的畫面。搶答中只顯示階段、倒數、各組是否在線，**不顯示任何作答資訊（含送出數量）**，以符合 C9。結束後老師可逐題揭曉或全部揭曉搶答成功組別與答案 | Default |
| D17 | 組別建立 | 老師在準備階段設定組數與組名 | Default |
| D18 | 老師身分 | 老師需輸入密碼才能進入老師端；密碼由環境變數設定 | Default |
| D19 | 重設活動 | 老師可在「已結束」後重設活動回到「準備中」（需再次確認）；組別保留，本次活動的作答資料清空 | Default |
| D20 | 數量限制 | 組名 1–30 字元且不重複；最多 50 組；倒數時間 10 秒至 60 分鐘 | Default |
| D22 | 題目敘述 | 匯入時若有題目敘述則一併讀取，作答區在題號旁顯示；沒有也不影響 | Default |
| D23 | 答案規則 | 每個空格的答案去除前後空白後 1–200 字元；不判斷對錯 | Default |
| D21 | 換組與重連 | 學生只能在「準備中」換組；重新整理或斷線重連後回到原組別與目前階段 | Default |

## 3. 共同驗收情境

每個子功能的規格會補上自己的 `AC-<子功能>-<序號>`。以下是整體流程的最低共同標準：

| ID | 情境 | 預期結果 | 需求 |
|---|---|---|---|
| AC-000-01 | 老師匯入官方單題範本 | 顯示 6 題 | C2 |
| AC-000-02 | 老師匯入官方題組範本 | 顯示 4 題，其中 2 題為題組（各 2 個空格） | C2, E1 |
| AC-000-03 | 老師匯入欄位位置不同的學習單 | 題數與空格正確，不因位置不同而出錯 | C2 |
| AC-000-04 | 老師開啟搶答 | 所有已進場的學生畫面在 2 秒內變成可作答 | C3, C6, C11 |
| AC-000-05 | A 組先送出第 1 題，B 組後送出 | 老師端看到 A 為第 1 順位、B 為第 2 順位；A、B 互相看不到對方狀態 | C4, C7, C9, C10 |
| AC-000-06 | 搶答中學生重新整理頁面 | 回到同一階段，自己組已送出的答案仍在 | C11 |
| AC-000-07 | 老師結束搶答 | 所有學生畫面在 2 秒內顯示結果；之後不能再送出 | C3, C8, C11 |
| AC-000-08 | 老師匯出回 Guided Notes | 每題填空格內是搶答成功組別的答案；沒有人作答的題目保持空白 | C5 |
| AC-000-09 | 老師匯出 CSV | 內容與老師端看到的順位一致 | E2 |
