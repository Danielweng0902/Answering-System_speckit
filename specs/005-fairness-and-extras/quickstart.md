# Quickstart: 公平順位與投影看板（005）

## 前置

依 [001 quickstart](../001-activity-session/quickstart.md)、[002 quickstart](../002-guided-notes-import/quickstart.md)、[003 quickstart](../003-buzz-in/quickstart.md)、[004 quickstart](../004-export/quickstart.md) 啟動系統（`npm run build && npm start`）並先 reset 到乾淨活動。

老師分頁 T；學生分頁至少兩個：第一組 A1、第二組 B。投影頁另開一個分頁（可用同一個瀏覽器的另一個分頁，**同一個分頁不要同時當老師端與投影頁**，避免搶答事件互相干擾）。

測試用學習單：`fixtures/guided-notes/02-official-group.xlsx`（第 1、2 題各有 2 個空格）。

## 自動驗證

```bash
npm test          # 含公平順位純函式、指令、揭曉、CSV 第 8 欄、投影快照無作答資訊
npm run test:e2e  # 含公平順位一輪作答、投影看板逐題揭曉
npm run check     # 型別、lint 與 PlantUML 圖檔檢查
```

## 人工驗證（對應驗收情境）

| 步驟 | 操作 | 預期 | 驗收情境 |
|---|---|---|---|
| 1 | T 在「準備中」打開「公平順位」開關 | 開關可切換，旁邊有一句規則說明；切換後其他分頁同步看到「本場使用公平順位」 | AC-005-09、AC-005-12 |
| 2 | T 在「搶答中」或「已結束」嘗試改公平順位 | 開關停用或直接呼叫指令被拒（`INVALID_PHASE`） | AC-005-10 |
| 3 | T 匯入 02 並確認（4 題、6 個空格） | 老師端顯示題號 1–4，第 1、2 題為題組 | 前置 |
| 4 | T 開啟搶答；投影頁 P 開在 `/projector` | P 以大字顯示「搶答中」，顯示倒數（若有設定）與各組是否在線；**看不到任何答案、送出狀態或送出數量** | AC-005-13、AC-005-14、SC-004 |
| 5 | A1 送出第 1 題後立刻看 P | P 仍只有階段、倒數、在線狀態；作答資訊一個字都沒有 | AC-005-14 |
| 6 | A1 送出第 1 題後 1 秒內，B 也送出第 1 題 | 兩者屬同一批（3 秒內）；B 搶答成功（成功題數 0 題 < A1 的 0 題時依送達先後，故 A1 為第 1 順位、B 為第 2；用第 2 題觀察輪替更清楚） | AC-005-01、AC-005-03 |
| 7 | A1 在第 2 題送出（此時 A1 成功 1 題、B 成功 0 題），B 在 3 秒內也送出第 2 題 | 第 2 題的搶答成功組別是 B（成功題數較少） | AC-005-01、SC-001 |
| 8 | B 送出第 1 題但距第一個答案超過 3 秒 | B 不屬於同一批，順位排在該批之後；搶答成功組別不變 | AC-005-02 |
| 9 | T 看作答看板 | 尚未滿 3 秒的題目標示「判定中」；3 秒後翻成最終順位 | AC-005-08 |
| 10 | T 作廢 A1 第 1 題的作答 | 該題重新判定（若 A1 是唯一有效作答則該題變無人作答）；**後面已判定的題目也依新的成功題數重算**，各組成功題數與題目判定一致 | AC-005-19、D25 |
| 11 | T 結束搶答 | 學生端與結果畫面標示「本場使用公平順位」；因公平順位而由非最先送達者搶答成功的題目有標示 | AC-005-11 |
| 12 | 學生端在搶答中看作答區 | 只知道自己組的狀況，看不到其他組是否已送出，也看不到自己的順位 | AC-005-12 |
| 13 | T 在已結束狀態按「揭曉下一題」 | 投影頁出現**下一個題號**的搶答成功組別與答案；尚未揭曉的題目不顯示 | AC-005-16、AC-005-17（依題號順序） |
| 14 | T 連續按「揭曉下一題」直到全部揭曉 | 依題號順序逐題出現；最後顯示各組搶答成功的題數 | AC-005-17、AC-005-18 |
| 15 | T 按「全部揭曉」 | 一次顯示所有題目結果與各組成功題數 | AC-005-17、AC-005-18 |
| 16 | T 匯出 CSV | 欄位變成 8 欄，最後一欄是「公平順位」；啟用時為 `是`，因公平順位改判的題目為 `是（改判）`；未啟用的活動為 `否` | FR-011、D13 v0.5 |
| 17 | 未登入（或以學生身分）開啟 `/projector` | 提示需要老師身分，看不到任何結果 | AC-005-18、FR-022 |
| 18 | T 重設活動 | 公平順位回到不啟用、揭曉進度清空、學生端回到準備中 | FR-001、FR-023 |
| 19 | 關閉搶答前重開伺服器，再看結果 | 結果與重開前完全相同（判定只依已保存的送達資料） | FR-009、SC-003 |

步驟 6～10 需要能輸入答案的活動；若不便操作，以自動測試的案例為準（`server/tests/unit/answerSettlement.test.ts` 與 `server/tests/integration/fairnessCommands.test.ts`）。

## 投影看板的檢視方式

投影頁是既有 SPA 的 `/projector` 路由，會用老師的 token 以 `view: 'projector'` 連線。要確認「作答資訊沒有送到瀏覽器」，除了看畫面，還要用 DevTools Network／WebSocket Messages 檢查 `state` 封包內容（`ProjectorSnapshot` 不含答案欄位）。這與 003 步驟 6／15 的檢查方式相同。
