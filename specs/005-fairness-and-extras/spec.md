# Feature Specification: 公平順位與投影看板（fairness-and-extras）

**Feature Branch**: `005-fairness-and-extras`

**Created**: 2026-11-10

**Status**: Draft

**Input**: User description: "更公平的搶答順位機制，鼓勵還沒搶答成功的組別參與；以及適合課堂投影的看板。依 docs/shared/FEATURE-CONTRACT.md 決策 D14、D16。"

**對應需求**：E3（公平順位）、E4（投影看板；倒數計時已在 001）

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 公平順位：讓還沒搶答成功的組別有優先權（Priority: P1）

老師在開啟搶答前可以選擇啟用「公平順位」。啟用後，某一題第一個答案送達後的 3 秒內送達的組別視為同一批。同一批當中，目前搶答成功題數最少的組別優先成為該題的搶答成功組別；題數相同時再比送達的先後。沒有啟用時，一律由最先送達的組別搶答成功。

**Why this priority**: 屬於額外功能 E3。單純比快會讓少數手快的組別拿走大部分題目，其他組別失去參與動機。

**Independent Test**: 啟用公平順位後，讓已經搶答成功 2 題的第一組先送出第 3 題，1 秒後尚未搶答成功的第二組也送出，確認第 3 題的搶答成功組別是第二組。

**Acceptance Scenarios**:

1. **AC-005-01**（E3）**Given** 已啟用公平順位、第一組已搶答成功 2 題、第二組 0 題，**When** 第一組先送出第 3 題、第二組在 3 秒內也送出，**Then** 第 3 題的搶答成功組別是第二組，第一組為第 2 順位。
2. **AC-005-02**（E3）**Given** 已啟用公平順位，**When** 第二組在第一個答案送達的 3 秒之後才送出，**Then** 第二組不屬於同一批，搶答成功組別仍是第一組。
3. **AC-005-03**（E3）**Given** 已啟用公平順位、同一批中的兩組搶答成功題數相同，**When** 判定順位，**Then** 先送達的組別優先。
4. **AC-005-04**（E3, C10）**Given** 沒有啟用公平順位，**When** 任何組別送出，**Then** 一律由最先送達的組別搶答成功，行為與 003 相同。
5. **AC-005-05**（E3）**Given** 已啟用公平順位，**When** 某一題只有一個組別在 3 秒內送出，**Then** 該組搶答成功。
6. **AC-005-06**（E3）**Given** 已啟用公平順位、某一題的 3 秒還沒過完，**When** 老師結束搶答，**Then** 以結束當下已送達的答案判定該題。
7. **AC-005-07**（E3）**Given** 某一題的搶答成功組別已經判定，**When** 之後其他題目的結果改變了各組的成功題數，**Then** 已判定的題目不再改變。
8. **AC-005-08**（E3, C4）**Given** 已啟用公平順位、某一題還在 3 秒內，**When** 老師查看看板，**Then** 該題的順位標示為「判定中」，3 秒後顯示最終順位。

### User Story 2 - 老師選擇是否啟用公平順位（Priority: P1）

老師在「準備中」階段決定本次活動是否啟用公平順位。啟用與否在老師端、結果畫面與匯出的紀錄中都看得到，讓所有人知道這場活動用的是哪一種規則。

**Why this priority**: 課程核心需求是「最快搶答的組別選定為搶答成功」，公平順位改變了這個結果，所以必須是老師明確的選擇，預設不啟用。

**Independent Test**: 分別以啟用與不啟用開啟兩場活動，以相同的送出順序作答，比較結果。

**Acceptance Scenarios**:

1. **AC-005-09**（E3）**Given** 活動在「準備中」，**When** 老師查看活動設定，**Then** 看到「公平順位」選項，預設為不啟用，並有一句話說明規則。
2. **AC-005-10**（E3）**Given** 活動在「搶答中」或「已結束」，**When** 老師嘗試變更公平順位設定，**Then** 系統拒絕。
3. **AC-005-11**（E3, C8）**Given** 活動以啟用公平順位進行並結束，**When** 學生查看結果，**Then** 畫面標示本場使用公平順位；因公平順位而非最先送達卻搶答成功的題目有標示。
4. **AC-005-12**（E3, C9）**Given** 已啟用公平順位、活動在「搶答中」，**When** 學生查看作答區，**Then** 知道本場使用公平順位，但仍看不到任何其他組別的狀況與自己的順位。

---

### User Story 3 - 投影看板（Priority: P2）

老師可以開啟一個適合投影到教室螢幕的看板。搶答進行中，看板顯示活動階段、倒數時間與各組是否已進場，不顯示任何作答資訊。結束後，老師可以在看板上逐題揭曉搶答成功的組別與答案。

**Why this priority**: 屬於額外功能 E4，提升課堂上的參與感與節奏，但沒有它核心流程仍可完成。

**Independent Test**: 開啟投影看板後進行一場活動，確認搶答中看板沒有任何作答資訊；結束後逐題揭曉，內容與老師端的結果一致。

**Acceptance Scenarios**:

1. **AC-005-13**（E4）**Given** 老師已登入，**When** 開啟投影看板，**Then** 看板以適合遠距離觀看的大字顯示目前階段。
2. **AC-005-14**（E4, C9）**Given** 活動在「搶答中」，**When** 查看投影看板，**Then** 只看到階段、倒數時間（有設定時）與各組是否在線；看不到任何答案、哪一組已送出、或各題的送出數量。
3. **AC-005-15**（E4, C11）**Given** 投影看板開啟中，**When** 活動階段改變，**Then** 看板在 2 秒內同步。
4. **AC-005-16**（E4, C8）**Given** 活動已結束，**When** 老師在投影看板按「揭曉下一題」，**Then** 看板顯示下一題的搶答成功組別與答案；尚未揭曉的題目不顯示結果。
5. **AC-005-17**（E4）**Given** 活動已結束，**When** 老師按「全部揭曉」，**Then** 看板顯示所有題目的結果與各組搶答成功的題數。
6. **AC-005-18**（E4）**Given** 未以老師身分登入，**When** 嘗試開啟投影看板，**Then** 系統要求老師登入。

---

### Edge Cases

- 公平順位下，兩題的 3 秒時間重疊：依各題第一個答案送達的先後依序判定；先判定的題目會影響後判定題目所用的成功題數。
- 公平順位下，同一批中有三組以上：依成功題數由少到多排序，相同者依送達先後。
- 公平順位下，系統在某題的 3 秒內重新啟動：重啟後以已保存的送達時間重新判定，結果與沒有重啟時相同。
- 投影看板在「準備中」：顯示等待畫面與已進場的組別。
- 投影看板逐題揭曉的進度只影響投影看板，不影響學生畫面（學生在結束時已看到全部結果）。
- 無人作答的題目在揭曉時顯示無人作答。
- 重設活動後：公平順位設定回到預設（不啟用），揭曉進度清空。

## Requirements *(mandatory)*

### Functional Requirements

**公平順位**

- **FR-001**（E3）: 老師 MUST 能在「準備中」階段選擇是否啟用公平順位；預設為不啟用；進入「搶答中」後 MUST NOT 能變更。
- **FR-002**（E3, C10）: 未啟用時，搶答成功的判定 MUST 與 003 相同：最先送達者搶答成功。
- **FR-003**（E3）: 啟用時，某題第一個答案送達後 3 秒內送達的所有作答 MUST 視為同一批。
- **FR-004**（E3）: 同一批中，MUST 由「目前搶答成功題數」最少的組別取得第 1 順位；題數相同時依送達先後。同一批的其餘組別依相同規則排序。
- **FR-005**（E3）: 不屬於同一批的作答，順位 MUST 排在同一批之後，並依送達先後排序。
- **FR-006**（E3）: 「目前搶答成功題數」MUST 只計算已經完成判定的題目。
- **FR-007**（E3）: 一題在其 3 秒時間結束時完成判定；活動結束時尚未完成判定的題目 MUST 以當下已送達的作答立即判定。
- **FR-008**（E3）: 題目依第一個答案送達的先後依序判定；已完成判定的題目 MUST NOT 再改變。
- **FR-009**（E3）: 判定 MUST 只依據系統保存的送達時間與順序，重新計算時 MUST 得到相同結果。
- **FR-010**（E3, C4）: 老師看板 MUST 將尚未完成判定的題目標示為判定中。
- **FR-011**（E3, C8）: 結果畫面與匯出的紀錄 MUST 標示本場是否啟用公平順位；因公平順位而由非最先送達者搶答成功的題目 MUST 有標示。
- **FR-012**（E3, C9）: 啟用公平順位 MUST NOT 讓學生在「搶答中」看到任何其他組別的狀況或自己的順位。

**投影看板**

- **FR-013**（E4）: 老師 MUST 能開啟投影看板；看板 MUST 只有老師可以開啟。
- **FR-014**（E4）: 投影看板 MUST 以適合遠距離觀看的方式顯示目前階段與倒數時間（有設定時）。
- **FR-015**（E4, C9）: 「搶答中」階段，投影看板 MUST NOT 顯示任何答案、任何組別的送出狀態、或任何送出數量。
- **FR-016**（E4）: 「準備中」與「搶答中」階段，投影看板 MUST 顯示各組是否有成員在線。
- **FR-017**（E4, C8）: 「已結束」階段，老師 MUST 能在投影看板逐題揭曉或全部揭曉結果；未揭曉的題目 MUST NOT 顯示結果。
- **FR-018**（E4）: 全部揭曉後，投影看板 MUST 顯示各組搶答成功的題數。
- **FR-019**（E4, C11）: 投影看板 MUST 在階段改變或揭曉後 2 秒內更新。

### Key Entities

- **活動設定（Activity Settings）**: 本場活動的選項。屬性：是否啟用公平順位。
- **判定批次（Batch）**: 某題第一個答案送達後 3 秒內的作答集合。
- **題目判定（Settlement）**: 一題的判定狀態：判定中或已判定，以及判定時間。
- **揭曉進度（Reveal Progress）**: 投影看板上已揭曉到第幾題。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 啟用公平順位、6 個組別以相同速度作答 6 題時，搶答成功題數最多與最少的組別相差不超過 1 題。
- **SC-002**: 未啟用公平順位時，所有題目的結果 100% 與「最先送達者搶答成功」一致。
- **SC-003**: 以同一組送達紀錄重新判定 100 次，結果 100% 相同。
- **SC-004**: 「搶答中」階段，投影看板上的作答資訊為 0 項。
- **SC-005**: 投影看板的文字在一般教室後排（約 8 公尺）可以辨識。
- **SC-006**: 老師可以用一句話向學生說明公平順位的規則。

## Assumptions

- 公平順位的時間長度固定為 3 秒（Feature Contract D14），不提供調整。
- 公平順位預設不啟用，以確保課程核心需求「最快搶答的組別選定為搶答成功」在預設情況下成立。
- 投影看板與老師端的作答狀況看板（003）是不同的畫面：前者公開投影、不含作答資訊；後者只有老師自己看。
- 倒數計時已在 001 定義，本子功能只在投影看板上顯示它。
- 逐題揭曉只是投影看板的呈現方式，不改變學生端在結束時即可看到結果的規則（C8）。
- 本子功能依賴 001、002、003；004 的匯出須包含公平順位的標示。
- 行為規則來自 `docs/shared/FEATURE-CONTRACT.md` v0.1（Default，待 OpenSpec 組確認）。
