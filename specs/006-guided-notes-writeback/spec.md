# Feature Specification: 寫回線上 Google Sheets（guided-notes-writeback）

**Feature Branch**: `006-guided-notes-writeback`
**Created**: 2026-11-17
**Status**: Draft（待助教／兩組確認實作方式，尚未開始實作）
**Input**: 助教 2026-11-17 補充說明：「Guided Notes 以 Google Sheets 的形式儲存」指的是系統需**直接串接自己雲端線上的 Google Sheets 進行讀寫**，而非下載成 .xlsx 檔在本地端離線處理。

**對應需求**：C5（把答案寫回老師的學習單）、D12（兩組共同約定，即將改版）

## 為什麼有這個子功能

本專案原本把「匯出回 Guided Notes」定義為**產生同格式 xlsx 讓老師下載**（`specs/004-export/spec.md` FR-001），並把「直接寫回雲端試算表」列為未來的擴充。助教的補充說明指出這與課程規範不符：老師的學習單存在自己的雲端試算表，系統應直接對那份線上試算表讀寫，老師不需要把檔案下載下來再自己處理。

## 目前的實作與落差

| 面向 | 目前實作（002／004） | 助教的說明 | 落差 |
|---|---|---|---|
| 讀取 | 老師貼連結 → 伺服器直接連到線上 `docs.google.com/spreadsheets/d/<id>/export?format=xlsx` 取回內容並解析（老師不需自己下載檔案） | 「串接線上試算表讀寫」 | **讀取已是線上**；但是否必須改用 Sheets API 而非 export 端點，待確認 |
| 寫回 | 產生一份新的 xlsx 給老師下載；若要回到雲端，老師必須自己把檔案覆蓋回原本的試算表 | 系統直接寫回線上試算表 | **缺 write-back**，且目前的「老師手動覆蓋」正是助教說不可依賴的離線流程 |
| 授權 | 只需表單設為「知道連結者可檢視」，不需要任何帳號授權或金鑰（002 FR-002） | 需要寫入權限 | 寫入不能用「知道連結者可檢視」或 API key，必須新增授權方式 |
| 匯出來源是上傳的 xlsx | 沒有雲端目標，只能下載 | 助教未說明 | 待確認：此來源是否維持下載 |

## 已知技術選項（待選定）

| 選項 | 作法 | 老師端成本 | 伺服器端成本 |
|---|---|---|---|
| A. OAuth 2.0 老師授權 | 老師按「連結 Google 帳號」授權 `spreadsheets` scope，伺服器保存 refresh token 代為寫入 | 要點一次授權、可隨時解除 | 需要 client id／secret（環境變數）、redirect、token 儲存與更新、錯誤處理 |
| B. 服務帳號共用 | 老師把試算表另外共用給服務帳號信箱 | 多一步手動共用 | 需要服務帳號金鑰（環境變數）、共用檢查 |
| C. 保留下載、只做讀 | 維持現狀 | 不變 | 不變 |

寫入 API 以 `spreadsheets.values.batchUpdate`（只寫值、保留原格式）最合適：本專案已在 002 保存每個空格的 A1 座標（`blanks.cell`）與工作表名稱，寫回時可直接對映；02／04 兩種題組版面（前綴格與答案格分離／前綴在合併填答區）沿用 004 已實作的那套判定規則。
不建議改用 `spreadsheets.spreadsheets.batchUpdate` 重建整張表，會破壞老師原有的格式與公式。

## 開放問題（要問助教或老師）

1. 「讀寫」是否**必須**包含寫回線上試算表？（若只要讀取，我們已經符合，則此子功能取消。）
2. 匯出按鈕要改成「寫回線上試算表」取代「下載 xlsx」，還是兩者並存（寫回為主、下載為備援）？
3. 匯入來源是「上傳的 xlsx」時沒有雲端目標，這條路徑怎麼處理？
4. 授權要用哪一種：老師 OAuth 授權（A）還是服務帳號共用（B）？有沒有可用的 Google Cloud 專案／金鑰可以給我們？
5. 寫入失敗（例如權限不足、表單被改名）時，老師端要怎麼提示、要不要保留下載檔案作為備援？
6. 兩組是否都要做？課程要求兩組的使用者可見行為一致，這會影響 OpenSpec 組的排程。

## 與既有規格的關係

- `docs/shared/FEATURE-CONTRACT.md` D12 改版（v0.6）：由「產生 xlsx 下載」改為「對線上試算表讀寫」，待兩組同意。
- `specs/002-guided-notes-import/spec.md`：讀取已是線上；若採 OAuth，FR-002「不需要帳號授權」需調整。
- `specs/004-export/spec.md`：2026-11-14 記錄的「助教的回覆：維持現狀」與本次說明不一致，以本次說明為準時，寫回移到本子功能，004 保留 CSV 匯出與（可選的）xlsx 下載。
- 本子功能不取代 005（公平順位與投影看板）；若 004 保留 xlsx 下載，兩者都會用到同一套「答案 → 儲存格」判定。

## 建議的契約改版（D12 v0.6 草案，待兩組同意後才寫入 Feature Contract）

> **D12 匯出回 Guided Notes**｜老師的學習單存在自己的雲端 Google Sheets，系統須**直接對那份線上試算表讀寫**：讀取時連線取得最新內容，寫回時把搶答成功組別的答案直接寫入對應的填空格，不以「下載成 xlsx 再由老師手動覆蓋」作為主要流程。答案寫入仍須是純文字、不得被試算表當成公式；前綴與答案的版面規則同 v0.5（分離時答案寫右側獨立格、合併填答區保留「前綴＋答案」）。匯入來源是上傳的 xlsx 時沒有雲端目標，這條路徑維持下載。授權方式（老師 OAuth 或服務帳號共用）待助教確認。

> 狀態：Default（**待兩組同意**）。依 Feature Contract 的修改方式，兩組各至少一人同意後才寫入 `docs/shared/FEATURE-CONTRACT.md` 並升版。
