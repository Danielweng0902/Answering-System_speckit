# Feature Specification: 寫回線上 Google Sheets（guided-notes-writeback）

**Feature Branch**: `006-guided-notes-writeback`
**Created**: 2026-11-17
**Status**: Draft（**需求已確認**；授權方式由兩組自行決定並已定案：服務帳號共用；剩設定步驟與實作，尚未開始寫程式）
**Input**: 助教 2026-11-17 補充說明：「Guided Notes 以 Google Sheets 的形式儲存」指的是系統需**直接串接自己雲端線上的 Google Sheets 進行讀寫**，而非下載成 .xlsx 檔在本地端離線處理。

**對應需求**：C5（把答案寫回老師的學習單）、D12（兩組共同約定，即將改版）

**優先序**：此說明為**課程規範**，優先於 2026-11-14 記錄的「助教的回覆：維持現狀、產生 xlsx 下載」；那份紀錄作廢，以本說明為準（`specs/004-export/spec.md` 已加註）。

## 為什麼有這個子功能

本專案原本把「匯出回 Guided Notes」定義為**產生同格式 xlsx 讓老師下載**（`specs/004-export/spec.md` FR-001），並把「直接寫回雲端試算表」列為未來的擴充。助教的補充說明指出這與課程規範不符：老師的學習單存在自己的雲端試算表，系統應直接對那份線上試算表讀寫，老師不需要把檔案下載下來再自己處理。

**因此本子功能是確定需求，不是選項**：老師匯入的是線上 Google Sheets，活動結束後答案要直接寫回那份線上試算表。

## User Scenarios & Testing

### User Story 1 - 一鍵寫回線上試算表（Priority: P1）

活動結束後，老師按「寫回 Google 試算表」，系統就把每題搶答成功組別的答案寫進他原本那份線上學習單的對應填空格。老師不需要下載檔案、再自己上傳覆蓋。

**Why this priority**: 這是助教說明的核心要求；沒有它，流程就等於助教說不可依賴的離線處理。

**Independent Test**：用連結匯入一份線上試算表，做完一場活動後按寫回，確認該試算表對應的填空格裡出現答案，且原本的格式與其他內容沒變。

**Acceptance Scenarios**:

1. **AC-006-01**（C5）**Given** 老師以 Google Sheets 連結匯入學習單、活動已結束，**When** 按「寫回 Google 試算表」，**Then** 系統把答案寫進該試算表對應的填空格，並回報寫入幾格。
2. **AC-006-02**（C5, E1）**Given** 題組的前綴格與答案格是分開的兩格（官方 02），**When** 寫回，**Then** 前綴格保持原樣，答案寫在右側的獨立答案格。
3. **AC-006-03**（C5, E1）**Given** 題組的前綴位於合併填答區內（官方 04），**When** 寫回，**Then** 該合併格寫入「前綴＋答案」。
4. **AC-006-04**（C5）**Given** 某些題沒有人作答，**When** 寫回，**Then** 那些題目的填空格完全不動。
5. **AC-006-05**（C5）**Given** 老師是上傳 xlsx 匯入的（沒有線上試算表），**When** 按寫回，**Then** 系統說明沒有雲端目標並提示改用下載 xlsx。

### User Story 2 - 寫回失敗時老師看得到原因、還有備援（Priority: P1）

寫回可能失敗：沒有編輯權限、試算表被改名、暫時連不上。課堂中不能就卡住，系統要說清楚原因，並保留「下載 xlsx」這條路。

**Why this priority**: 寫入線上服務一定有失敗率；沒有清楚的失敗處理，課堂流程會被卡住。

**Acceptance Scenarios**:

1. **AC-006-06**（C5）**Given** 試算表還沒共用給服務帳號，**When** 寫回，**Then** 系統說明「沒有編輯權限」並提示可以改成下載 xlsx。
2. **AC-006-07**（C5）**Given** 試算表不存在或暫時無法寫入，**When** 寫回，**Then** 系統顯示對應的中文原因，且不中斷其他功能。
3. **AC-006-08**（C5）**Given** 伺服器沒有設定服務帳號，**When** 寫回，**Then** 系統說明尚未設定並提示改用下載 xlsx。
4. **AC-006-09**（C5）**Given** 學生身分或活動還沒結束，**When** 直接呼叫寫回 API，**Then** 系統拒絕（`FORBIDDEN`／`INVALID_PHASE`），不寫入任何東西。

## Requirements

### Functional Requirements

- **FR-001**（C5）: 系統 MUST 提供「寫回 Google 試算表」的操作，只有老師、只有在「已結束」階段可用。
- **FR-002**（C5）: 寫回 MUST 只寫入搶答成功組別的答案值，MUST NOT 改變老師原本的格式、公式與版面（只用 `values.batchUpdate`）。
- **FR-003**（C5, E1）: 寫入的儲存格 MUST 與 004 匯出 xlsx 時完全一致：前綴格與答案格分離時寫右側獨立格；前綴在合併填答區時寫該合併格並保留前綴；單題寫原格。
- **FR-004**（C5）: 沒有人作答的題目 MUST NOT 被寫入任何內容。
- **FR-005**（C5）: 寫回 MUST 是唯讀本地資料的動作：作答、題目、階段、revision 都 MUST NOT 改變。
- **FR-006**（C5）: 寫入需要編輯權限，系統 MUST 用服務帳號認證；金鑰 MUST 只存在環境變數，MUST NOT 進版控、資料庫或 log（原則 IV）。
- **FR-007**（C5）: 寫回失敗時 MUST 回傳可讀的中文原因，並在老師端提示可以改用下載 xlsx；失敗 MUST NOT 中斷其他功能。
- **FR-008**（C5）: 匯入來源是上傳的 xlsx 時 MUST 回「沒有雲端目標」並提示下載；此路徑的 xlsx 下載 MUST 保留。
- **FR-009**（C5）: 老師端 MUST 顯示寫入結果（寫入幾格或失敗原因），且 MUST 保留既有的「匯出 Guided Notes」「匯出 CSV」功能。
- **FR-010**（C5）: log MUST 只記錄寫入的格數，MUST NOT 記錄答案內容、token、金鑰或試算表內容（原則 IV）。

### Success Criteria

- **SC-001**: 寫回後，線上試算表對應填空格的內容與老師端看到的搶答成功答案 **100% 一致**。
- **SC-002**: 寫回 **0 個**非答案儲存格（老師原本的題目、格式、公式都不動）。
- **SC-003**: 失敗時老師端 **100%** 看得到中文原因與下載備援提示。
- **SC-004**: 寫回動作 **0 次**改變本地資料（作答、題目、階段、revision）。


## 目前的實作與落差

| 面向 | 目前實作（002／004） | 助教的說明 | 落差 |
|---|---|---|---|
| 讀取 | 老師貼連結 → 伺服器直接連到線上 `docs.google.com/spreadsheets/d/<id>/export?format=xlsx` 取回內容並解析（老師不需自己下載檔案） | 「串接線上試算表讀寫」 | **讀取已是線上**；但是否必須改用 Sheets API 而非 export 端點，待確認 |
| 寫回 | 產生一份新的 xlsx 給老師下載；若要回到雲端，老師必須自己把檔案覆蓋回原本的試算表 | 系統直接寫回線上試算表 | **缺 write-back**，且目前的「老師手動覆蓋」正是助教說不可依賴的離線流程 |
| 授權 | 只需表單設為「知道連結者可檢視」，不需要任何帳號授權或金鑰（002 FR-002） | 需要寫入權限 | 寫入不能用「知道連結者可檢視」或 API key，必須新增授權方式 |
| 匯出來源是上傳的 xlsx | 沒有雲端目標，只能下載 | 助教未說明 | 待確認：此來源是否維持下載 |

## 已知技術選項（待選定）

| 選項 | 作法 | 老師端成本 | 伺服器端成本 |
|---|---|---|---|
| A. OAuth 2.0 老師授權 | 老師按「連結 Google 帳號」授權 `spreadsheets` scope，伺服器保存 refresh token 代為寫入 | 要點一次授權、可隨時解除 | 需要 client id／secret（環境變數）、redirect、token 儲存與更新、錯誤處理 |
| B. 服務帳號共用 | 老師把試算表另外共用給服務帳號信箱 | 多一步手動共用 | 需要服務帳號金鑰（環境變數）、共用檢查 |
| C. 保留下載、只做讀 | 維持現狀 | 不變 | 不變 |

寫入 API 以 `spreadsheets.values.batchUpdate`（只寫值、保留原格式）最合適：本專案已在 002 保存每個空格的 A1 座標（`blanks.cell`）與工作表名稱，寫回時可直接對映；02／04 兩種題組版面（前綴格與答案格分離／前綴在合併填答區）沿用 004 已實作的那套判定規則。
不建議改用 `spreadsheets.spreadsheets.batchUpdate` 重建整張表，會破壞老師原有的格式與公式。

## 開放問題（只剩實作方式，不影響「要寫回」這個決定）

1. **服務帳號金鑰要放在哪**：老師自行建立自己的服務帳號，還是由團隊建一組共用？前者老師要自己摸 Google Cloud，後者老師只要共用一次信箱。→ 預設由**團隊建一組共用服務帳號**，老師只做「共用」一步。
2. **寫入失敗時的老師端提示**（沿用既有錯誤代碼風格）與是否自動提供下載備援。→ 預設顯示可讀原因＋提供下載按鈕。
3. **兩組的實作分工**：錯誤處理、介面與目標儲存格規則要對齊；若兩組用同一組服務帳號，老師只需要共用一次。

（以上三點由兩組自行協調，不需再詢問助教。）

## 我們的決定（2026-11-17，兩組自行處理，不再詢問助教）

| 項目 | 決定 | 理由 |
|---|---|---|
| 授權方式 | **服務帳號共用**：老師把試算表另外共用給我們的服務帳號信箱，伺服器用該服務帳號的金鑰呼叫 Sheets API | 不需要每位老師做 OAuth 授權與授權流程；伺服器端不必保存每位老師的 token，錯誤與逾時單一處理。讀取維持現況（連結＋「知道連結者可檢視」），只有寫回需要編輯權限 |
| 憑證保管 | 服務帳號金鑰只放 `.env`（已 gitignore），不放進 repo、不進 log | 憲法原則 IV（機敏資料零落地） |
| 讀取 | 維持現況：伺服器直接連線線上試算表取回最新內容 | 已經是線上行為，且已驗證過格式／合併範圍的解析 |
| 寫入 | `spreadsheets.values.batchUpdate`，只寫答案值到指定儲存格 | 保留老師原有的格式、公式與版面；不重建整張表 |
| 目標儲存格 | 沿用 004 已實作的判定：02 分離版面寫右側獨立格、04 合併填答區寫「前綴＋答案」、單題寫原格 | 兩種匯出來源行為一致，且已有回歸測試 |
| 寫回與下載 | **兩者並存**：線上寫回為主（來源是連結時），xlsx 下載保留為備援 | 上傳 xlsx 匯入的老師沒有雲端目標；寫入失敗時也要有備援 |
| 失敗處理 | 寫入失敗（權限不足／表單改名或刪除／限流／逾時）時：老師端顯示可讀原因＋「改用下載 xlsx」按鈕，不中斷整個活動 | 課堂中不宜失敗就卡住；錯誤訊息不夾帶 token 或回應內容 |
| 兩組 | 兩組都做，且盡量共用同一組服務帳號 | 老師只要共用一次就能在兩套系統使用；也讓兩組的使用者行為一致 |

### 仍需人工做的事（不是需求問題，是設定步驟）

1. 建立（或沿用）一個 Google Cloud 專案，開啟 Google Sheets API，建立服務帳號並下載金鑰 → 放進 `.env`（例如 `GOOGLE_SERVICE_ACCOUNT_EMAIL`、`GOOGLE_SERVICE_ACCOUNT_PRIVATE_KEY`）。
2. 把服務帳號信箱（`…@….iam.gserviceaccount.com`）提供給老師，讓老師在該試算表的「共用」裡把它加為編輯者。
3. 金鑰只存在老師的機器上（`.env`），不進版控、不貼到群組訊息或 issue。

## 實作計畫草案（授權方式已定案）

| 階段 | 內容 |
|---|---|
| 1. 寫入連接層 | 以 004 已實作的「答案 → 目標儲存格」判定（02 分離格／04 合併填答區）為基礎，做一個 `SheetWriter` 介面；先用假的 client 寫測試，之後接真正的 Google API |
| 2. 目標儲存格對映 | 002 已保存每個空格的 A1 座標（`blanks.cell`）與工作表名稱；寫回時以 `spreadsheets.values.batchUpdate` 只寫值、保留原格式與公式 |
| 3. 授權與設定 | 依助教選定的方式：OAuth 流程或服務帳號共用；憑證只放 `.env`（已 gitignore），伺服器只保存必要的 token |
| 4. 匯出流程與介面 | 老師端改為「寫回 Google 試算表」為主流程（來源是連結時），顯示寫入結果（成功／失敗原因／可改下載） |
| 5. 錯誤與逾時 | 逾時、限流、無編輯權限、表單不存在等錯誤以既有錯誤代碼風格處理，訊息不夾帶 token 或回應內容（原則 IV） |
| 6. 驗證 | 單元（目標儲存格、請求內容）、整合（假 API 伺服器 → 實際請求內容與錯誤）、人工（真的寫回一份線上試算表並確認格式保留） |

**不採用的做法**：用 `spreadsheets.spreadsheets.batchUpdate` 重建整張表（會破壞老師的格式與公式）；把老師的試算表整份下載到本機再上傳（正是助教說不可依賴的離線流程）。

## 建議的契約改版（D12 v0.6 草案，待兩組同意後才寫入 Feature Contract）

> **D12 匯出回 Guided Notes**｜老師的學習單存在自己的雲端 Google Sheets，系統須**直接對那份線上試算表讀寫**：讀取時連線取得最新內容，寫回時把搶答成功組別的答案直接寫入對應的填空格，不以「下載成 xlsx 再由老師手動覆蓋」作為主要流程。答案寫入仍須是純文字、不得被試算表當成公式；前綴與答案的版面規則同 v0.5（分離時答案寫右側獨立格、合併填答區保留「前綴＋答案」）。匯入來源是上傳的 xlsx 時沒有雲端目標，這條路徑維持下載。授權方式（老師 OAuth 或服務帳號共用）待助教確認。

> 狀態：Default（**待兩組同意**）。依 Feature Contract 的修改方式，兩組各至少一人同意後才寫入 `docs/shared/FEATURE-CONTRACT.md` 並升版。
