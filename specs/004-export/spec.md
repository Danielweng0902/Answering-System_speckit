# Feature Specification: 匯出結果（export）

**Feature Branch**: `004-export`

**Created**: 2026-11-10

**Status**: Draft

**Input**: User description: "老師把搶答成功組別的答案匯出回原 Guided Notes 的填空格，並可把活動結果匯出成 CSV。依 docs/shared/FEATURE-CONTRACT.md 決策 D12、D13。"

**對應需求**：C5（主要）、E2

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 把搶答成功的答案寫回原 Guided Notes（Priority: P1）

活動結束後，老師按「匯出 Guided Notes」，得到一份與當初匯入的學習單格式相同的試算表檔，其中每一題的填空格已填入該題搶答成功組別的答案。老師可以直接開啟，或匯回 Google Sheets。

**Why this priority**: 課程核心需求：答案須寫入原本題目的填空格。對應 C5。

**Independent Test**: 匯入官方單題範本、讓兩組作答後結束，匯出並開啟檔案，確認每一題的填空格是搶答成功組別的答案，其他內容與格式與原檔相同。

**Acceptance Scenarios**:

1. **AC-004-01**（C5；對應 AC-000-08）**Given** 活動已結束且第 1 題由第一組搶答成功、答案為「CPU」，**When** 老師匯出 Guided Notes，**Then** 檔案中第 1 題的填空格內容是「CPU」。
2. **AC-004-02**（C5）**Given** 某一題無人作答，**When** 匯出，**Then** 該題的填空格與原檔相同（保持空白）。
3. **AC-004-03**（C5）**Given** 匯出的檔案，**When** 與原檔比較，**Then** 除了填填空格外，標題、題號、題目敘述、合併儲存格、欄寬、框線、字型都與原檔相同。
4. **AC-004-04**（C5；2026-11-16 修訂）**Given** 匯入的是版面不同的學習單（fixture 01～05），**When** 作答、結束並匯出，**Then** 單題答案寫至 `expected.json` 所列格；題組則依原檔 merge range 判斷——前綴與答案格分離時保持前綴格、把答案寫到右側獨立格，前綴位於合併填答區時在該區保留前綴並寫答案，沒有錯寫其他儲存格。
5. **AC-004-05**（C5）**Given** 活動在「準備中」或「搶答中」，**When** 老師嘗試匯出 Guided Notes，**Then** 系統不提供或拒絕此操作，並說明結束後才能匯出。
6. **AC-004-06**（C5）**Given** 學生（非老師），**When** 嘗試匯出，**Then** 系統拒絕。
7. **AC-004-07**（C5）**Given** 同一場已結束的活動，**When** 老師匯出兩次，**Then** 兩次的內容相同。
8. **AC-004-16**（C5；003 D24）**Given** 某組對第 1 題的作答被老師作廢且該組未再送出，**When** 老師匯出 Guided Notes，**Then** 第 1 題的填空格維持原檔內容，不寫入被作廢的答案。

---

### User Story 2 - 題組答案依原版面寫入正確填答格（Priority: P2）

題組的前綴「（1）」「（2）」有兩種合法版面：一種與答案格分開（如 02），一種位於合併填答區內（如 04）。匯出 MUST 依原檔 merge range 判斷：分開時保持前綴格、答案寫右側獨立格；合併時在該填答區保留前綴並寫答案。

**Why this priority**: 屬於 E1 題組在匯出端的行為；人工驗證證明 02 的紙本版面與先前「一律同一格」設計不一致，回歸也發現 04 不能一律右移。

**Independent Test**: 匯入官方題組範本與 mixed fixture，讓題組由某組搶答成功後匯出，確認 02 的前綴格不變且答案在右側獨立格，04 的合併填答區保留前綴並含答案。

**Acceptance Scenarios**:

1. **AC-004-08**（C5, E1）*人工驗證修訂；2026-11-16 兩組同意* **Given** `02-official-group.xlsx` 題組第 1 題搶答成功的答案為「CPU」與「作業系統」，**When** 匯出，**Then**「（1）」「（2）」原格保持原樣，右側兩個獨立答案格分別是「CPU」與「作業系統」。
2. **AC-004-09**（C5, E1）**Given** 題組無人作答，**When** 匯出，**Then** 前綴格與答案格都維持原檔內容。

---

### User Story 3 - 匯出活動結果 CSV（Priority: P2）

活動結束後，老師按「匯出 CSV」，得到一份包含所有組別、所有題目作答紀錄的檔案：題號、組別、答案、順位、是否搶答成功、送出時間。

**Why this priority**: 屬於額外功能 E2，讓老師保存完整紀錄。

**Independent Test**: 兩組各送出數題後結束並匯出 CSV，用試算表軟體開啟，確認每一列與老師看板的內容一致，中文沒有亂碼。

**Acceptance Scenarios**:

1. **AC-004-10**（E2；對應 AC-000-09）**Given** 活動已結束，**When** 老師匯出 CSV，**Then** 每一筆作答的每一個空格各占一列，欄位依序為：題號、空格序、組別、答案、順位、是否搶答成功、送出時間。
2. **AC-004-11**（E2）**Given** 匯出的 CSV，**When** 與老師看板比較，**Then** 每一題各組的答案、順位、搶答成功標示完全一致。
3. **AC-004-12**（E2）**Given** 匯出的 CSV，**When** 用常見的試算表軟體直接開啟，**Then** 中文正確顯示，沒有亂碼。
4. **AC-004-13**（E2）**Given** 答案中含有逗號、引號或換行，**When** 匯出，**Then** 該答案仍在同一個欄位內，不會錯位。
5. **AC-004-14**（E2）**Given** 答案以 `=`、`+`、`-`、`@` 開頭，**When** 用試算表軟體開啟 CSV，**Then** 該內容顯示為文字，不會被當成公式執行。
6. **AC-004-15**（E2）**Given** 沒有任何組別作答，**When** 匯出 CSV，**Then** 得到只有欄位名稱列的檔案。
7. **AC-004-17**（E2；003 D24）**Given** 某組對第 1 題的作答被老師作廢且該組未再送出，**When** 老師匯出 CSV，**Then** 該筆作答不產生任何列，CSV 只含有有效作答。

---

### Edge Cases

- 活動沒有匯入過題目：不能匯出，系統說明原因。
- 匯入來源是 Google Sheets 連結：匯出的仍是可下載的試算表檔；系統不直接修改雲端上的試算表。
- 填空格原本已有非前綴的內容（例如前一次的答案）：有搶答成功答案時以新答案取代；無人作答時保持原內容。
- 答案很長：完整寫入，不截斷。
- 答案以 `=` 等字元開頭：寫入 Guided Notes 時也必須是文字，不能變成公式。
- 啟用公平順位機制（005）時：匯出使用的搶答成功組別與結果畫面顯示的相同；CSV 的欄位維持 D13 的 7 欄，是否啟用公平順位由 005 另行決定是否加欄。
- 重設活動之後：原活動的結果已清空，不能再匯出。
- 某組的作答被老師作廢且該組未再送出（003 的 D24）：該筆作答不算有效作答，不寫入 Guided Notes 的填空格，也不出現在 CSV；作廢紀錄只在系統內保留供稽核。
- 以 exceljs 讀寫原檔會產生細微格式變化：匯出必須確保文字內容、合併範圍、欄寬、框線與字型皆保留；技術上無法達成時改為直接修改 xlsx 內部 XML，不得放寬驗收標準。

## Requirements *(mandatory)*

### Functional Requirements

**匯出回 Guided Notes**

- **FR-001**（C5）: 老師 MUST 能在「已結束」階段匯出一份試算表檔，內容為當初匯入的學習單，並在每一題的填空格寫入該題搶答成功組別的答案。
- **FR-002**（C5）: 單題答案 MUST 使用 002 依結構解析保存的 `blanks.cell` 作為寫入位置；題組若 `blanks.cell` 含前綴且與答案格分離，前綴格 MUST 保留，答案 MUST 依原檔結構填入右側獨立答案格。MUST NOT 依固定儲存格位置寫入。
- **FR-003**（C5）: 除填空格外，匯出檔的內容與格式 MUST 與原檔相同，包含合併儲存格、欄寬、框線、字型。驗收以逐項比對原檔與匯出檔為準；若讀寫原檔的技術路線無法保留這些格式，MUST 改用能保留的寫入方式，不得放寬此要求。
- **FR-004**（C5）: 無人作答的題目，其填空格 MUST 維持原檔的內容。
- **FR-005**（C5, E1；2026-11-16 修訂）: 題組的前綴 MUST 保留，不得在前綴格或獨立答案格重複輸出。原檔的前綴格與答案格分開時，前綴格保持原樣、右側獨立格只寫學生答案；前綴位於合併填答區內時，該合併格是答案格，內容為「前綴＋答案」，MUST NOT 盲目右移到邏輯上不存在的獨立答案格。
- **FR-006**（C5）: 寫入的答案 MUST 是純文字，不得被試算表軟體當成公式。
- **FR-007**（C5）: 匯出檔的檔名 MUST 為「搶答結果_日期時間.xlsx」的形式，能辨識是搶答結果與匯出時間；不論匯入來源為上傳檔或 Google Sheets 連結皆使用此規則。
- **FR-008**（C5）: 匯出 MUST NOT 修改系統保存的原檔；同一場活動重複匯出的內容 MUST 相同。

**匯出 CSV**

- **FR-009**（E2）: 老師 MUST 能在「已結束」階段匯出 CSV，包含所有組別對所有題目的有效作答紀錄；被老師作廢的作答不算有效作答，不列入 CSV。
- **FR-010**（E2）: CSV 的欄位 MUST 依序為：題號、空格序、組別、答案、順位、是否搶答成功、送出時間；第一列為欄位名稱。欄位數與順序依 Feature Contract D13，005 實作公平順位時再由兩組同意調整。
- **FR-011**（E2）: 一筆作答的每個空格各占一列；列的順序為題號、順位、空格序。
- **FR-012**（E2）: CSV MUST 能被常見試算表軟體直接開啟且中文不亂碼。
- **FR-013**（E2）: 含有逗號、引號、換行的內容 MUST 正確保留在同一欄位。
- **FR-014**（E2）: 以 `=`、`+`、`-`、`@` 開頭的內容 MUST 以不會被當成公式的方式輸出。
- **FR-015**（E2）: CSV 的順位與搶答成功標示 MUST 與老師看板及結果畫面一致。

**權限與條件**

- **FR-016**（C5, E2）: 兩種匯出 MUST 只有老師可以執行，且只在「已結束」階段。
- **FR-017**（C5）: 活動沒有題目時，系統 MUST 拒絕匯出並說明。

### Key Entities

- **匯出的 Guided Notes**: 原檔的副本加上搶答成功答案。屬性：檔名、產生時間。
- **結果紀錄列（Result Row）**: CSV 的一列。屬性：題號、空格序、組別、答案、順位、是否搶答成功、送出時間。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: `fixtures/guided-notes/` 中 5 份有效學習單，匯出後每個答案 100% 位於依 `expected.json` 定位資料與原檔 merge range 判定的正確答案格（02 右側獨立格、04 合併填答區、單題原格）。
- **SC-002**: 匯出檔中，填空格以外的儲存格內容 100% 與原檔相同，且合併範圍、欄寬、框線、字型皆保留。
- **SC-003**: 老師從按下匯出到取得檔案，在 5 秒內完成。
- **SC-004**: CSV 的每一列與老師看板的對應資料 100% 一致（有效作答；被作廢的作答不列入）。
- **SC-005**: 匯出的試算表檔可以匯回 Google Sheets 並保持原本的版面。

## Assumptions

- 「匯出至原 Guided Notes」以產生同格式、已填答案的試算表檔實現（Feature Contract D12）；直接寫回雲端試算表列為之後的擴充，本規格不包含。2026-11-14 確認維持此設計，系統不直接修改雲端上的試算表。
- 系統在匯入時已保存原檔與每個空格的位置（002）。
- 搶答成功組別與順位由 003（及啟用時的 005）決定，本子功能只讀取結果；被作廢的作答（003 D24）不視為有效作答。
- 送出的原始 UTC 時間以 003 系統收到的 `submissions.received_at` 為準；CSV 匯出時以伺服器本地時區呈現為 `YYYY-MM-DD HH:mm:ss.SSS`，不用 `Z` 或時區後綴，供老師直接閱讀。2026-11-16、兩組同意此修改，資料庫不變。
- 「是否搶答成功」以「是／否」表示。
- 行為規則來自 `docs/shared/FEATURE-CONTRACT.md` v0.4（D12、D13 為 Default；D24 已兩組同意）。
