# Quickstart: 活動與組別進場

## 前置

- Node.js 24 以上
- 在專案根目錄：`npm install`
- 複製 `.env.example` 為 `.env`，設定 `TEACHER_PASSWORD`（自訂，勿提交）

## 啟動

```bash
npm run build && npm start     # 單一伺服器，預設 http://localhost:3000
# 開發時：npm run dev
```

## 自動驗證

```bash
npm test                       # 單元與整合測試
npm run test:e2e -- 001        # E2E：老師＋兩組學生
npm run check                  # 型別檢查、lint、圖表檢查
```

預期：全部通過。

## 人工驗證（對應驗收情境）

準備三個瀏覽器分頁：A 開 `/teacher`，B、C 開 `/student`。

| 步驟 | 操作 | 預期 | 驗收情境 |
|---|---|---|---|
| 1 | A 輸入錯誤密碼 | 顯示密碼錯誤，留在登入畫面 | AC-001-12 |
| 2 | A 輸入正確密碼 | 進入老師端，階段為準備中 | AC-001-11 |
| 3 | A 不建立組別直接按開啟搶答 | 被拒絕並提示先建立組別 | AC-001-04 |
| 4 | A 新增「第一組」「第二組」 | B、C 的組別選單在 2 秒內出現兩組 | AC-001-14、06 |
| 5 | A 新增空白、重複、31 個字的組名 | 各自被拒絕並說明原因 | AC-001-15 |
| 6 | B 選第一組、C 選第二組 | 各自顯示組名與「準備中」 | AC-001-07 |
| 7 | A 以 30 秒倒數開啟搶答 | A、B、C 在 2 秒內顯示搶答中，剩餘時間一致 | AC-001-01、22 |
| 8 | B 重新整理頁面 | 仍是第一組、搶答中 | AC-001-18 |
| 9 | A 嘗試新增組別 | 被拒絕 | AC-001-16 |
| 10 | 等倒數歸零 | 三個分頁在 2 秒內顯示已結束 | AC-001-23 |
| 11 | 重新啟動伺服器（Ctrl+C 後 `npm start`） | 三個分頁重連後仍是已結束，組別還在 | AC-001-21 |
| 12 | A 按重設活動並確認 | 三個分頁回到準備中，組別保留 | AC-001-27 |

未設定 `TEACHER_PASSWORD` 的情況另外驗證：移除 `.env` 中的設定後啟動，A 登入應顯示需要先設定密碼（AC-001-13）。

人工驗證的結果記錄在 `docs/verification/`。

介面合約見 [contracts/](./contracts/)，資料模型見 [data-model.md](./data-model.md)。
